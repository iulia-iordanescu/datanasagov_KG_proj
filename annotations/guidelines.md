# Annotation guidelines

What to write in the [ground truth](../docs/terminology.md#4-ground-truth-and-samples), and how, so that anyone annotating a record writes the same [classed triples](../docs/terminology.md#2-triples). For how to use the [annotation tool](../docs/terminology.md#4-ground-truth-and-samples) (`py helpers/annotate.py`), see [README.md](README.md), *Annotating ground truth: the annotation tool*. Terms: [docs/terminology.md](../docs/terminology.md).

The ground truth is the answer key extraction (step 060) is evaluated against (step 070). So every rule below is also a rule the model follows when it drafts (step 050) and extracts (step 060), and when it extracts the [triple instances](../docs/terminology.md#2-triples) the schema is learned from (step 040): the shared rules in `common/common_prompts/extraction_rules.txt`. So you and the model follow the same rules. If they differed, step 070 would count the model wrong even where it followed its own rules correctly.

## Before you start

- **Work in pool order within each part, without skipping.** Make [drafted batches](../docs/terminology.md#4-ground-truth-and-samples) with `py 050_annotate/run.py` ([tuning records](../docs/terminology.md#7-evaluating-extraction-step-070) by default; `--part held-out` for held-out ones) and correct them in the order of the pool: a record after a gap in its own part (tuning or held-out) isn't evaluated until the records of that part before it are done; the other part is not held back (`docs/upkeep.md`, *After step 050 drafts a batch*).
- **Read the record's text first, then its ground truth triples.** The [drafted triples](../docs/terminology.md#4-ground-truth-and-samples) were written by a model: reading the text first makes it easier to see what they got wrong, and above all what it missed.
- **Annotate tuning records and [held-out records](../docs/terminology.md#7-evaluating-extraction-step-070) the same way: every fact (rule 2), whether or not the [ground truth schema](../docs/terminology.md#3-schemas) has an [entity class](../docs/terminology.md#3-schemas) or predicate for it.** The tool shows each record's part. An entity class or predicate you coin while annotating a held-out record is added to the ground truth schema marked held-out only: a line `held-out only` under it, and a `source:` line naming the held-out records (`ground truth held-out #8`). A [held-out-only entry](../docs/terminology.md#3-schemas) is never shown to a model (steps 040, 050, 060, the [second opinion](../docs/terminology.md#4-ground-truth-and-samples)), is never a target of the [translation table](../docs/terminology.md#7-evaluating-extraction-step-070), and is never cited to shape a rule, a check, or a definition of another entry; the records that use it are evaluated as any other (its [triples](../docs/terminology.md#2-triples) translate to nothing from the [current schema](../docs/terminology.md#6-extracting-with-a-schema-step-060), so they count as out of reach). While a held-out record is shown, you may add, redefine, rename or merge held-out-only entries only; an entry without the mark can't be touched (use the one that fits, or coin a marked one). A pattern a held-out record uses that no finished tuning record uses never becomes one of the ground truth schema's patterns (the tool flags it; if the entity classes and direction are right, keep the triple). A tuning record may not use a held-out-only entry: the tool flags it (✖) and offers **Unmark**, which drops the line and names the tuning record in the source: the entry then joins the ground truth schema every model sees, and its definition should be read again then, since it was written from a held-out record. Unmark it only when a tuning record needs the entry; the held-out records keep using it. Why: the held-out records measure how well the pipeline works on records it was never adjusted to; a definition or a rule shaped by them would adjust it to them, but a fact left out of their [ground truth](../docs/terminology.md#4-ground-truth-and-samples) would hide a miss (rule 2: "nothing else catches the omission"). Decided on 2026-11-01; until then the ground truth schema was frozen for held-out records, and a fact no entry fitted was left out.

## What counts as a fact

1. **Only what the record states.** Never add what you know from elsewhere, and never write down what an unexplained code or abbreviation stands for, its [entity class](../docs/terminology.md#3-schemas) included: an unexplained code gets no [ground truth triple](../docs/terminology.md#4-ground-truth-and-samples) whose meaning depends on what it stands for. A code counts as explained when it follows one of these catalog conventions: "V" or "Version" followed by a number (a version); "L" or "Level" followed by a number (a processing level). Any other code needs the record's own explanation. The list of conventions is closed: a new one is added only by a decision recorded in [docs/improvements.md](../docs/improvements.md). **Names on an official NASA list.** A name the record doesn't explain gets its entity class, and nothing else, when one of these official NASA lists names it, for the record's own mission or platform, as an instance of that entity class: the Global Change Master Directory's (GCMD) Instruments or Platforms keywords, or the Planetary Data System's PDS4 context products. The name is written as the record writes it, never expanded, and the list gives no other fact. The list and its entry go in a note of the record's section in `annotations/left_out.md`, in the item that leaves out what the name stands for. *Suppose:* a record titled "ROSETTA-ORBITER 67P RSI 1/2/3 COMET ESCORT 4 1149 V1.0" never says what "RSI" is, and the PDS4 context product urn:esa:psa:context:instrument:ro.rsi is "The Radio Science Investigations (RSI) for the Rosetta Orbiter", an instrument of the Rosetta Orbiter. *Then:* [the record's dataset](../docs/terminology.md#1-records-and-their-text) ACQUIRED_BY_INSTRUMENT "RSI" (Instrument), with the source text "RSI"; "Radio Science Investigations" is not written. The record may be one part of a longer record ("part 1 of 2"); state only what this part states. A fact the record does not state in one passage may be written when the record's own statements meet one of the three tests below; never infer from outside knowledge. The list of tests is closed, like the list of conventions: a new one is added only by a decision recorded in docs/improvements.md. The [source text](../docs/terminology.md#1-records-and-their-text) of such a fact is the passages that meet the test, each copied exactly, joined by " … " (rule 17 of *Writing a classed triple*). (To see that two wordings name the same thing, you may use what the words mean: rule 23 of *Writing a classed triple*.)
    - **Replacement.** When the record says an older one is discontinued or decommissioned and directs users to a newer one, the newer one SUPERSEDES the older one (SUPERSEDES's definition in the [ground truth schema](../docs/terminology.md#3-schemas) says the same). *Suppose:* a record says "The MOD11A1 Version 6 data product was decommissioned on July 31, 2023. Users are encouraged to use the MOD11A1 Version 6.1". *Then:* "Version 6.1" SUPERSEDES "Version 6".
    - **Comparison.** When the record says one named thing is lower, higher, better (or any other comparison) without saying than what, and names exactly two things of that kind together, the other of the two is what the first is compared with; with three or more, no fact. *Suppose:* a record says "Two SST products can be present in these files. The first is a skin SST", and later "The SST4 product has lower uncertainty". *Then:* "SST4" HAS_LOWER_UNCERTAINTY_THAN "skin SST".
    - **Membership by name.** When the title or an identifier of the record's dataset contains the name of a group of datasets the record describes, the record's dataset is a member of the group. A statement about the group is then written for the record's dataset only when it holds for each member alone: it says "all" or "each", or it gives a property that every member has (a version, a grid, access terms). A statement about the group as a whole is not written for it: what the members cover taken together, "either … or", what the data have been used for, how many members there are. *Suppose:* a record titled "BARREL 4G Rate Counter (RCNT) NaI Scintillator Diagnostics, Level 2, 4 s Data" says "The current release of all BARREL CDF data products are Version 10 files" and "BARREL observations collected near latitudes close to either the antarctic and arctic circles". *Then:* the record's dataset HAS_VERSION "Version 10" ("all"; "current" is left out by rule 10). The latitudes give no ground truth triple: "either" makes them true of the observations taken together, not of this dataset's.
2. **Every fact the record states, unless a rule leaves it out:** rule 1 above and rules 3 to 10 below, and rules 16, 20, 21 and 24 of *Writing a classed triple*, or it waits on an expert's answer (`annotations/questions_for_experts.md`). The rule holds whether or not the ground truth schema has an entity class or predicate for the fact. Leaving out any other fact is the worst mistake: a fact missing from the [ground truth](../docs/terminology.md#4-ground-truth-and-samples) counts extraction wrong when extraction finds that fact (lower precision), and makes recall look better than it is when extraction misses the fact too; nothing else catches the omission. The title states facts too. *Suppose:* a title says "MODIS/Aqua Snow Cover 5-Min L2 Swath 500m V061", and the notes name MODIS and Aqua separately. *Then:* among others, the record's dataset ACQUIRED_BY_INSTRUMENT MODIS, and HAS_SPATIAL_RESOLUTION "500m".
3. **Not the field names.** The record's text is split into its [text fields](../docs/terminology.md#1-records-and-their-text) (`title:`, `notes:`, …); the field names are formatting, not facts. *Suppose:* a record's text starts "title: …" and "notes: …". *Then:* no ground truth triple comes from the words "title" or "notes".
4. **Not "is a" facts.** "MODIS is a spectroradiometer" says what type of thing MODIS is: that belongs in its entity class, not in a [classed triple](../docs/terminology.md#2-triples) of its own. A sentence that names one specific role is not an "is a" fact, though: *Suppose:* a record says "JPL is the official Physical Oceanography Data Archive (PO.DAAC) for SST". *Then:* a ground truth triple, because it names a role only JPL holds, not a type. A phrase that says what kind a thing is and also names another thing it belongs to states two facts (rule 15 of *Writing a classed triple*): the kind is left out, and the belonging is a ground truth triple. *Suppose:* a record says "Selected as a NASA Living with a Star Mission of Opportunity, BARREL was designed to …". *Then:* "BARREL" PART_OF "NASA Living with a Star"; "Mission of Opportunity" says what kind of mission BARREL is, and gives no ground truth triple.
5. **Not opinions.** Leave out words such as "great". *Suppose:* a record says "access great NASA technical information". *Then:* the instance is "NASA technical information".
6. **Not negated facts.** A ground truth triple can't say "not", and a negated fact is not rewritten into a fact the record doesn't state. *Suppose:* a record says "Data are not available before 2001." *Then:* no ground truth triple.
7. **Not facts the record doesn't assert as true:** uncertain ones, and ones it requires, requests or recommends. *Suppose:* a record says "The collection may include data from Terra." *Then:* no ground truth triple: the record doesn't state that it does. The same for "might", "possibly", and "is expected to" when it means "will probably". The same for "should", "are requested to", "are asked to", "are encouraged to", and "are expected to" when it means "must". *Suppose:* a record says "all users are expected to read and follow the BARREL Data Usage Policy". *Then:* no ground truth triple, because the record asks it of users and doesn't state that they do. A value given as approximate is stated, though. *Suppose:* a record says "a resolution of approximately 250 m". *Then:* one ground truth triple, with "approximately 250 m" as its [object instance](../docs/terminology.md#2-triples).
8. **Not the values inside a data table; only what the table is about.** Some records' `notes` fields include a table of measurements. *Suppose:* a record says "Table 1 lists, for each of the 18 clusters, its redshift, position and exposure time", followed by lines such as "RDCSJ 1317+2911 0.805 13 17 21 +29 11 19 2228 I VF 111.3". *Then:* write the facts about the record's dataset (among them: it has measurements of redshift, of position, and of exposure time; it covers 18 clusters), but no ground truth triple per cell ("RDCSJ 1317+2911" has redshift "0.805"): the values are the record's dataset's own data, not facts about it.
    - **A study a record tells.** When a record tells the study its dataset comes from, the study's aim and its method are facts of the record's dataset (HAS_PURPOSE; PRODUCED_USING_ALGORITHM, rule 24 of *Writing a classed triple*). The rest of the study is not: its background, its findings, what it says about methods it did not use, and the details of its method beyond what rule 24 of *Writing a classed triple* writes (how the method was applied, its parameters, what it allows). A finding is a result the study drew from the data, not what the data are, and the [knowledge graph](../docs/terminology.md#8-the-pipeline) is for finding the catalog's datasets. *Suppose:* a record says "In their study, the authors aimed to determine the ensemble variability properties of two serendipitously selected AGN samples … They used the structure function (SF) … They confirm a strong anti-correlation of the variability with X-ray luminosity". *Then:* the record's dataset HAS_PURPOSE "determine the ensemble variability properties of two serendipitously selected samples" (rule 19 of *Writing a classed triple* takes "AGN" out, a target body) and PRODUCED_USING_ALGORITHM "structure function (SF)"; the anti-correlation gives no ground truth triple.
9. **Not a fact without a specific thing.** A ground truth triple needs a subject and an object the record names. *Suppose:* a record says "MODIS captures data at a variety of spatial resolutions." *Then:* no ground truth triple, because "a variety of spatial resolutions" names no resolution. A fact the record states for each member of a group it names only by a count or a common noun ("186 parameters each with …", "Each product is …") is written for the thing the group belongs to only when it stays true of that thing: what it holds, what it measures, what it comes from, or what format its files are in. An amount or a count per member gives no ground truth triple, unless the predicate itself says "each" (HAS_GRANULE_DURATION, HAS_SPATIAL_RESOLUTION). *Suppose:* a record says "There are 186 parameters each with a data structure that contains the following: sampling rate, units". *Then:* the record's dataset HAS_ANCILLARY_DATA "sampling rate" and HAS_ANCILLARY_DATA "units", since a dataset holds what its parameters hold. *Suppose:* a record says "412 quasars that were observed by XMM-Newton from 2 to 25 epochs each". *Then:* the epochs give no ground truth triple: they are a count per quasar. A word that only says how another fact holds gives no ground truth triple, and is not part of an instance: its subject would be that fact, not a thing the record names. *Suppose:* a record says "The prime target is comet 67P/Churyumov-Gerasimenko 1 (1969 R1)". *Then:* the record's dataset HAS_TARGET "67P/Churyumov-Gerasimenko 1 (1969 R1)", without "prime": a prime target is a target. Such a word is kept when the record doesn't state the fact without it, that is, when the record's sentence doesn't imply the shorter one (the test of rule 19 of *Writing a classed triple*, *What stays in the instance*). The word is then part of what the predicate says when the object is an amount (rule 18), and part of the instance otherwise. *Suppose:* a record says "The useful vertical range of the data is 1000 to 0.01 hPa." *Then:* the sentence doesn't say that the data's vertical range is 1000 to 0.01 hPa, since the data may reach beyond it, so "useful" goes in the predicate: the record's dataset HAS_VERTICAL_RANGE "1000 to 0.01 hPa", whose definition is "its values can be used over this range of heights or pressures". What data have been used for, or can be used for, is a fact of the work that used them, not of the data: when the record doesn't name that work, it gives no ground truth triple. A use that names what was made from the data gives that product's input (rule 21 of *Writing a classed triple*). *Suppose:* a record says "the data has been used to characterize the spatial scale of precipitation". *Then:* no ground truth triple, because no work that used the data is named. *Suppose:* a record says "This dataset, A, is used to make dataset B." *Then:* "B" COMPUTED_FROM "A".
10. **Not words that are true only as of when the record was written.** Leave out "latest", "current", "now", "then available", and words like them. Keep the rest of the fact. *Suppose:* a record says "Version 2 is the latest version." *Then:* the record's dataset HAS_VERSION "Version 2", without "latest", because "latest" stops being true if another version is released. *Suppose:* a record says "V1.0 is the first version." *Then:* "V1.0" ALSO_KNOWN_AS "first version", because V1.0 stays the first version whatever is released later.

## Writing a classed triple

11. **[Subject instance](../docs/terminology.md#2-triples) and [object instance](../docs/terminology.md#2-triples): the record's own words, as written.** Don't paraphrase them, and don't expand an abbreviation the record leaves unexpanded. Exceptions: *What counts as a fact*, rules 5, 9 and 10 (opinion words, words that only say how another fact holds, and words true only as of writing, are left out); and rules 19, 20, 22, 23 and 24 below (rule 20: parentheses that hold the code of something else are not part of the instance; rule 24: the words for a processing step's input and method are not part of another instance). A period of time or a range of values is one instance, however it is worded (rule 22). A name stays whole: rules 19, 22 and 24 never split or shorten a name ("National Aeronautics and Space Administration (NASA)" keeps its "and"; "Earth Observation Satellites (EOS)" keeps "Earth"). One exception: a name made of the record's dataset's code and its version gives its parts as facts of their own, and a version so named is written as the version alone. A name of anything else that holds a version stays whole ("version 5 Hierarchical Data Format for the Earth Observing System (HDF-EOS5)", a file format, is one instance). *Suppose:* a record says "The MOD11A1 Version 6 data product". *Then:* [the record's dataset](../docs/terminology.md#1-records-and-their-text) HAS_IDENTIFIER "MOD11A1" and HAS_VERSION "Version 6".
12. **The subject instance is what the sentence is about**, which isn't always the title. A fact about the [describes triple](../docs/terminology.md#2-triples)'s object instance has that instance, the title, as its subject instance. *Suppose:* a record titled "ROSETTA-ORBITER 67P RSI 1/2/3 COMET ESCORT 4 1149 V1.0" says "This is a Rosetta Radio Science data set, collected during the COMET ESCORT 4 phase 2015-10-22 to 2015-12-31." *Then:* the facts about the record's dataset have the title as their subject instance: … FROM_MISSION "Rosetta" (Mission), … USES_TECHNIQUE "Radio Science" (Technique), … HAS_MISSION_PHASE "COMET ESCORT 4" (MissionPhase). But the dates belong to the phase, not to the record's dataset: "COMET ESCORT 4" (MissionPhase) HAS_TIME_SPAN "2015-10-22 to 2015-12-31" (Time). (From `annotations/ground_truth/batch_000.csv`, record `cfd6ec3f-1e63-4a77-bc3f-007d45f7e2fc`.)
13. **The predicate reads from subject to object**, as the [ground truth schema](../docs/terminology.md#3-schemas) defines it (`annotations/ground_truth_schema.txt`, section PREDICATES: "Each entry below reads subject -> object"). "Dataset ACQUIRED_BY_INSTRUMENT Instrument" means the dataset was collected by the instrument, not the other way round.
14. **[Entity classes](../docs/terminology.md#3-schemas) and predicates: the ground truth schema's**, when one fits, so records name the same things the same way. When none fits, coin one: see *Coining an entity class or predicate*, below.
15. **One fact per [ground truth triple](../docs/terminology.md#4-ground-truth-and-samples).** A sentence that states two facts gives two ground truth triples. *Suppose:* a record says "The data were collected by MODIS aboard Terra." *Then:* two ground truth triples: the record's dataset ACQUIRED_BY_INSTRUMENT "MODIS", and "MODIS" ABOARD "Terra".
16. **Each fact once,** even if the record states it twice or in other words. Rule 23 says which wording to keep. *Suppose:* a record says "This dataset provides daily snow cover", and later "snow cover is given each day". *Then:* the two sentences state one fact, so one ground truth triple: the record's dataset HAS_TEMPORAL_RESOLUTION "daily", the wording the record gives first (rule 23). (Two ground truth triples that are the same [classed triple](../docs/terminology.md#2-triples) in one record stop step 070 until one is deleted: `annotations/README.md`, *What the pipeline checks*.)
17. **[Source text](../docs/terminology.md#1-records-and-their-text), copied exactly.** 1. The shortest passage that contains words for the subject, the predicate and the object. 2. When the words for one of the three are only in another sentence, and no whole sentence lies between the two sentences, one passage from the earlier of the two (the fact, or the words for the missing one) to the end of the later. 3. Otherwise, the passages joined by " … " (every check also reads "…" or "..." between two passages, with or without spaces, as that join), in the record's order: the shortest passage with words for the missing one (and, when the fact's sentence names it in other words, the words that show the two wordings name one thing, rule 23), and the shortest passage with words for the rest. The title and the notes, and the passages that meet a test of rule 1 of *What counts as a fact*, are joined the same way (*Words in different places*, below). Select the passage in the record's text and press **Use selection**, so it is copied exactly; for case 3, copy the first passage so, then type " … " and the second passage after it. *Suppose:* a record says "The NASA Standards and Technical Assistance Resource Tool, or START, is a Web tool sponsored by the NASA Technical Standards Program. The idea is to make it simpler for technical people to access great NASA technical information quickly and conveniently". *Then:* the purpose's source text runs from "The NASA Standards and Technical Assistance Resource Tool, or START" to "conveniently" (case 2: the subject is named only in the sentence before the fact's, and no sentence lies between them). *Suppose:* a record says "The "HIRDLS/Aura Level 3 Geopotential Height Zonal Fourier Coefficients" version 7 data product (H3ZFCGPH) contains the entire mission (~3 years) of HIRDLS data", and three sentences later "Each file contains a zonal object with data for the entire mission". *Then:* the record's dataset HAS_GRANULE_DURATION "~3 years" has the source text "the entire mission (~3 years) … Each file contains a zonal object with data for the entire mission" (case 3: the first passage has the words for the object, and the words that show "the entire mission" means "~3 years"; the second states the fact).
    - **A title's facts.** For a fact the title states by its words alone, with no words for the predicate, the source text is the title's words for the object instance. *Suppose:* a title says "MODIS/Aqua Snow Cover 5-Min L2 Swath 500m V061", and the notes name MODIS and Aqua separately. *Then:* the record's dataset FROM_PLATFORM "Aqua" has the source text "Aqua".
    - **A name's facts.** For a fact a name in the notes states by its words alone, with no words for the predicate, the source text is the name as written. *Suppose:* a record says "These data are maps of fast neutron residual count rates from the GRaND plus Z boron loaded sensor". *Then:* "GRaND plus Z boron loaded sensor" PART_OF "GRaND" has the source text "GRaND plus Z boron loaded sensor". A band or channel named inside a Variable's words is such a fact: the Variable FOR_CHANNEL the band, and the Variable stays whole. *Suppose:* a record says "bands 31 and 32 emissivities". *Then:* "band 31 emissivity" FOR_CHANNEL "band 31" and "band 32 emissivity" FOR_CHANNEL "band 32", each with the source text "bands 31 and 32 emissivities".
    - **A platform in an instrument's name.** In the notes, a noun phrase that names an Instrument and begins with a Platform's name states that the Instrument is ABOARD the Platform, with the phrase as source text; the Instrument's instance follows rule 23 (the wording the record uses for the instrument alone, when it does; the whole name when it never does, rule 11). 1. The Platform must be one by the record's words or by rule 1's *Names on an official NASA list*. 2. A title's words are a list of facts of the record's dataset, not a name ("MODIS/Terra", "MODIS Aqua", "DAWN GRAND", "VG1 J/S/SS PWS"): FROM_PLATFORM and ACQUIRED_BY_INSTRUMENT, and no ABOARD (*A title's facts*). 3. A "/" or "+" between the two names, in the title or the notes, is a list (rule 22, *Lists joined by "/" or "+"*), not a name: no ABOARD. 4. The instrument's name first and the platform's after it ("MODIS Aqua data") is such a list too. *Suppose:* a record titled "MODIS/Terra Land Surface Temperature/Emissivity Daily L3 Global 1km SIN Grid V006" says "Production of V6 Terra MODIS Land Surface Temperature and Emissivity (LST&E) data products was discontinued", and names "MODIS" alone elsewhere. *Then:* "MODIS" (Instrument) ABOARD "Terra" (Platform), with the source text "Terra MODIS"; the title's "MODIS/Terra" gives the record's dataset ACQUIRED_BY_INSTRUMENT "MODIS" and FROM_PLATFORM "Terra", and no ABOARD of its own. *Suppose:* a record says "acquired by the Rosetta Orbiter ALICE UV Spectrometer", and never names the instrument otherwise. *Then:* "Rosetta Orbiter ALICE UV Spectrometer" (Instrument) ABOARD "Rosetta Orbiter" (Platform), the name kept whole (rule 11).
    - **An instrument in a channel's name.** In the notes, a Channel whose words begin with an Instrument's name states that the Channel is CHANNEL_OF the Instrument, with the Channel's words as source text; the Channel's instance stays whole (rule 11: a name stays whole), and the Instrument's follows rule 23. The Instrument must be one by the record's words or by rule 1's *Names on an official NASA list*. A title's words are a list of the record's dataset's facts, not a name (*A title's facts*): no CHANNEL_OF from a title. *Suppose:* a record says "VNP43D12 is the BRDF geometric parameter for VIIRS band M4 (0.555 μm)", and names "Visible Infrared Imaging Radiometer Suite (VIIRS)". *Then:* "VIIRS band M4 (0.555 μm)" (Channel) CHANNEL_OF "Visible Infrared Imaging Radiometer Suite (VIIRS)" (Instrument), with the source text "VIIRS band M4 (0.555 μm)". (From `annotations/ground_truth/batch_004.csv`, record `0eedd2bc-b2e2-4cc1-a94d-41c141169334`.)
    - **The thing the title names.** For a fact about the thing the title names (the describes triple's object instance, rule 12), the words for that thing may be left out of the source text. *Suppose:* a record titled "MODIS/Aqua Snow Cover 5-Min L2 Swath 500m V061" says "This global Level-2 (L2) data set provides daily snow cover". *Then:* the record's dataset HAS_TEMPORAL_RESOLUTION "daily" may have the source text "provides daily snow cover".
    - **Words in different places.** When the words for the subject, the predicate and the object are in different places, the source text is those passages, each copied exactly, joined by " … ", in one of these three cases: 1. the title and the notes; 2. the passages that meet a test of rule 1 of *What counts as a fact*; 3. two passages of the notes with a whole sentence between them (case 3 above). *Suppose:* a title says "MODIS Aqua Level 3 SST MID-IR 8 Day 4km Nighttime V2019.0", and the notes say "At night, a second SST product is generated using the mid-infrared 3.95 and 4.05 micron wavelength channels which are unique to MODIS; the SST derived from these measurements is identified as SST4". *Then:* the source text of the record's dataset HAS_VARIABLE "SST4" is the title's "SST MID-IR" and that passage of the notes, joined by " … ".
18. **A number with a unit: the object instance is the number and its unit, as written; what the number measures goes in the predicate.** *Suppose:* a record says "MODIS has a spatial resolution of 250 m." *Then:* "MODIS" HAS_SPATIAL_RESOLUTION "250 m".
19. **A qualifier that is a temporal resolution, an area the data cover, a processing level, a spatial resolution, a country, a time of day, or a target body is a ground truth triple of its own, and is taken out of the instance.** *Suppose:* a record says "This global dataset provides daily snow cover." *Then:* the record's dataset HAS_MEASUREMENTS_OF "snow cover", HAS_TEMPORAL_RESOLUTION "daily", and HAS_SPATIAL_COVERAGE "global". *Suppose:* a record says "This dataset holds nighttime SST." *Then:* the record's dataset HAS_MEASUREMENTS_OF "SST" and OBSERVED_AT_TIME_OF_DAY "nighttime". *Suppose:* a record names "the U.S. National Aeronautics and Space Administration (NASA)". *Then:* the instance is "National Aeronautics and Space Administration (NASA)", and "National Aeronautics and Space Administration (NASA)" BASED_IN "U.S." is a ground truth triple too. *Suppose:* a record says "The map is related to the average atomic mass on Vesta." *Then:* the instance is "average atomic mass", and the record's dataset HAS_TARGET "Vesta" is a ground truth triple of its own.
    - **A processing level.** A processing level is a level the record names as one: "Level" or "L" followed by a number (rule 1 of *What counts as a fact*), a level of a named scheme ("CODMAC level 2"), or a word the record itself calls a level ("processing level: Raw"). A word that only says how far the data are processed ("raw", "edited", "calibrated", "derived") is not a processing level, and stays in the instance, as written. *Suppose:* a title says "CH1-ORB MOON M3 2 L0 RAW NEAR-IR SPECTRAL IMAGES V1.0", and the notes say "raw near-IR spectral image cubes". *Then:* the record's dataset HAS_PROCESSING_LEVEL "L0", and "raw" stays in "raw near-IR spectral image cubes".
    - **Whose fact it is.** The new ground truth triple's subject depends only on the entity class of the instance the qualifier was in, not on the record's other facts. 1. When that entity class is a [standalone entity class](../docs/terminology.md#3-schemas) (its instances exist on their own and have facts of their own, e.g. Dataset, Organization, MissionPhase), the subject is that instance. 2. When that entity class is a [describing entity class](../docs/terminology.md#3-schemas) (its instances only describe something else, e.g. PhysicalQuantity, Purpose), the subject is the subject of the ground truth triple whose object the instance was, in the sentence the qualifier is in. The ground truth schema marks each entity class as one or the other (`rule 19: standalone` or `rule 19: describing`, on a line under it). *Suppose:* a record names "the U.S. National Aeronautics and Space Administration (NASA)". *Then:* NASA is an Organization, a standalone entity class, so "National Aeronautics and Space Administration (NASA)" BASED_IN "U.S.". *Suppose:* a record says "the L2 pixels are binned into an integerized sinusoidal area grid". *Then:* "pixels" is a Dataset, a standalone entity class, so "pixels" HAS_PROCESSING_LEVEL "L2". *Suppose:* a record says "The map is related to the average atomic mass on Vesta." *Then:* "average atomic mass" is a PhysicalQuantity, a describing entity class, so the record's dataset HAS_TARGET "Vesta".
    - **A country.** 1. A country that qualifies a specific Person or Organization (one the record names, rule 9 of *What counts as a fact*) is BASED_IN of that Person or Organization, and of no other, whatever entity class holds its words. 2. A country that qualifies what is measured is an area the data cover (HAS_SPATIAL_COVERAGE). 3. A country that qualifies persons or organizations the record doesn't name stays in the instance, as written. *Suppose:* a record says "This dataset holds U.S. precipitation." *Then:* "U.S." qualifies what is measured, not a Person or an Organization, so the record's dataset HAS_MEASUREMENTS_OF "precipitation" and HAS_SPATIAL_COVERAGE "U.S." (case 2). (In "the U.S. National Aeronautics and Space Administration (NASA)", it qualifies an Organization: BASED_IN, case 1.) *Suppose:* a record says a working group is "dedicated to identifying and addressing Earth observation needs across U.S. civilian federal agencies". *Then:* "U.S." qualifies the agencies, which are not named, so it stays (case 3): the group HAS_PURPOSE "identifying observation needs across U.S. civilian federal agencies" ("Earth" is taken out, a target body), with no BASED_IN.
    - **Ground and water words.** A word naming a kind of ground or water ("land", "ocean", "sea", "ice") stays in the instance if "the [rest] of the [word]" is true, and is an area the data cover if it is false. *Suppose:* a record says "Ocean Cloud Cover" and "Ocean Surface Temperature". *Then:* "the cloud cover of the ocean" is false, because the clouds are in the sky, so the record's dataset HAS_MEASUREMENTS_OF "Cloud Cover" and HAS_SPATIAL_COVERAGE "Ocean". "The temperature of the ocean surface" is true, so "Ocean Surface Temperature" stays whole.
    - **What stays in the instance.** A qualifier stays in the instance, as written, if it is any other kind ("sea surface salinity" stays whole), or if taking it out would give a [triple](../docs/terminology.md#2-triples) that isn't true. *Suppose:* a record says "an afternoon orbit". *Then:* taking "afternoon" out would give "orbit" OBSERVED_AT_TIME_OF_DAY "afternoon", which says the orbit comes from observations made in the afternoon. That isn't true, so the instance stays "afternoon orbit".
20. **A name with its own abbreviation, another name or code of its own, or a short note in parentheses is one instance, as written.** *Suppose:* a record says "This Level-2 (L2) dataset". *Then:* the instance is "Level-2 (L2)", with no ALSO_KNOWN_AS triple. An abbreviation set off by commas right after the words it abbreviates is the same as one in parentheses: one instance, as written, with its commas. It is an abbreviation only when each of its letters is a letter of those words, in the same order, and its first letter starts the first of them (the test of Schwartz and Hearst, 2003); otherwise the commas separate the items of a list (rule 22). *Suppose:* a record says "trajectories in Heliographic, HG, Heliographic Inertial, HGI, and Solar Ecliptic, SE, Coordinates". *Then:* "HG", "HGI" and "SE" spell the words just before them, so the list has three items, and rule 22 copies "Coordinates" onto each: "Heliographic, HG, Coordinates", "Heliographic Inertial, HGI, Coordinates" and "Solar Ecliptic, SE, Coordinates", with no ALSO_KNOWN_AS triple. A short note is a gloss of the thing named: another wording of it, its code, or a word that says what it is ("weekly (8 day)", "EDR (raw)"). Parentheses that state a fact of their own that the ground truth schema has a predicate for (a period, a duration, an amount, a place) give a ground truth triple of their own, and are taken out of the instance, as rule 19 takes out a qualifier. *Suppose:* a record says "The product contains modified Copernicus Sentinel data (2024-2025)". *Then:* the record's dataset COMPUTED_FROM "Copernicus Sentinel data", and "Copernicus Sentinel data" HAS_TIME_SPAN "2024-2025" (rule 21: the facts of what the record's dataset is made from). Parentheses that hold the code of something else are not part of the instance. *Suppose:* a record says "This data set contains Level 2/3 (EDR/RDR) data" and "The RDR data convert the EDR (raw) sensor data". *Then:* the record uses "EDR" and "RDR" as names of the data, not of the levels, so the levels are "Level 2" and "Level 3": "EDR (raw) sensor data" HAS_PROCESSING_LEVEL "Level 2", and "RDR data" HAS_PROCESSING_LEVEL "Level 3". Write ALSO_KNOWN_AS only when the record gives the other name in words of its own; the other ground truth triples then use one of the two wordings (rule 23). *Suppose:* a record says "The terms 'Version 61' and 'Collection 6.1' are used interchangeably in reference to this release". *Then:* the record's dataset HAS_VERSION "Version 61", and "Version 61" ALSO_KNOWN_AS "Collection 6.1". One exception, for the thing the title names (rule 23, *The thing the title names*): rule 23 writes it as its title in every ground truth triple, so an abbreviation the notes give it in parentheses would be lost. 1. When the parenthesised short name passes the abbreviation test above, write the thing the title names ALSO_KNOWN_AS the short name, as written and with the same entity class, with the name and its parentheses as source text. 2. When it fails the test, it is a code: HAS_IDENTIFIER (Identifier), as before. *Suppose:* a record titled "OPERA Dynamic Surface Water Extent from Sentinel-1 (Version 1)" says "This dataset contains Level-3 Dynamic OPERA Surface Water Extent from Sentinel-1 (DSWx-S1) product version 1". *Then:* D, S, W, x, S and 1 are letters of "Dynamic", "Surface", "Water", "Extent" and "Sentinel-1", in that order, so the record's dataset ALSO_KNOWN_AS "DSWx-S1" (Dataset), with the source text "Dynamic OPERA Surface Water Extent from Sentinel-1 (DSWx-S1)"; every later fact of "DSWx-S1" is the record's dataset's (rule 23). *Suppose:* a record says "The "HIRDLS/Aura Level 3 Geopotential Height Zonal Fourier Coefficients" version 7 data product (H3ZFCGPH)". *Then:* H3ZFCGPH fails the test, so the record's dataset HAS_IDENTIFIER "H3ZFCGPH" (Identifier).
    - **A page named, or given as an address.** 1. A page or site the record gives only as an address is a WebPage, the address as written. 2. A page or site the record names in words, without a web address, is a Document, named as written (rule 23 leaves out lowercase type words such as "mission web site"). 3. A link that gives both a name and an address ("[name](address)"): the address, a WebPage, when it is a web address; the name, a Document, when the address is a DOI (a DOI is an Identifier of what it names; parentheses that hold the code of something else are not part of the instance, above). *Suppose:* a record says "compiled by referencing several BARREL related resources including primarily the Millan et al. (2013) Space Science Reviews publication, the BARREL at Dartmouth mission web site". *Then:* the record's dataset DOCUMENTED_AT "BARREL at Dartmouth" (Document). *Suppose:* a record says "Details regarding methodology are available on the [VNP43MA1](https://doi.org/10.5067/VIIRS/VNP43MA1.002) product page". *Then:* the record's dataset DOCUMENTED_AT "VNP43MA1 product page" (Document); the DOI is another product's identifier (rule 21) and is not written. *Suppose:* a record says "please refer to the [MODIS/VIIRS Land Quality Assessment website](https://landweb.modaps.eosdis.nasa.gov/knownissue)". *Then:* the record's dataset DOCUMENTED_AT "https://landweb.modaps.eosdis.nasa.gov/knownissue" (WebPage), and the name gives no ALSO_KNOWN_AS (the record gives it in no words of its own, above).
21. **General facts: include them; about [another dataset](../docs/terminology.md#1-records-and-their-text), only when the record links it to the record's dataset by "part of" or "made from".**
    - **Include** a general fact (one true beyond this record) about something the record's dataset relates to, such as its instrument, its platform, or its mission. *Suppose:* a record says MODIS is aboard the Aqua satellite. *Then:* "MODIS" ABOARD "Aqua" is a ground truth triple. Something the record's dataset relates to is the subject or the object of a ground truth triple of this record that is connected to the record's id (*Finishing a record*). A statement that only explains a concept (what a term means, how a quantity behaves in general, which methods are in common use) and is about nothing so connected gives no ground truth triple: the [knowledge graph](../docs/terminology.md#8-the-pipeline) is for finding the catalog's datasets (rule 8 of *What counts as a fact*). *Suppose:* a record says its coordinates "have been calculated by using the Equinox Epoch: defined via the "Mean of Date" method", and also that the First Point of Aries "drifts by about 1.4° per century", and that "Four methods for determining the Equinox Epoch are in common usage". *Then:* the record's dataset PRODUCED_USING_ALGORITHM "Mean of Date". The drift and the three methods the data did not use give no ground truth triple: the First Point of Aries and those methods are the subject or object of no ground truth triple connected to the record's id.
    - **Another dataset.** Include facts about another dataset when the record states a chain of "part of" or "made from" links that connects it to the record's dataset: its parts, what it is part of, what it is made from, and so on through further datasets or variables the record names. Leave out facts about other datasets, such as a variant of the record's dataset (the same data at another temporal resolution, spatial resolution, or version), or a product made from it. In every case, include the connection the record states (rule 1 of *What counts as a fact*: only what the record states). *Suppose:* a record says "This dataset, A, is used to make dataset B. B covers 2001 to 2005." *Then:* "B" COMPUTED_FROM "A" is a ground truth triple, and "2001 to 2005" is left out, because it is a fact about B, which is made from the record's dataset. *Suppose:* a record says "Dataset C was used to make this dataset, A. C covers 2001 to 2005." *Then:* "A" COMPUTED_FROM "C" and "C" HAS_TIME_SPAN "2001 to 2005" are both ground truth triples, because the record's dataset is made from C. *Suppose:* a record says "This data set contains Level 2/3 (EDR/RDR) data" and "The RDR data convert the EDR (raw) sensor data". *Then:* the facts about "RDR data" and "EDR (raw) sensor data" are ground truth triples, because they are parts of the record's dataset. *Suppose:* a record's title says "8 Day", and its notes say "daily, weekly (8 day), and monthly products are available from this instrument's output". *Then:* the record's dataset HAS_TEMPORAL_RESOLUTION "weekly (8 day)", its own (by rule 23, it says more than "8 Day"); the daily and monthly products are variants of the record's dataset, and the record states no connection beyond that, so they get no ground truth triple.
22. **A list: one ground truth triple per item.** Apply rule 19 first. Then write one ground truth triple per item of the list, in which that item alone takes the list's place (the subject or the object), with the words the items share copied onto the item. Each such ground truth triple names one item, so shared words that agree with the number of items are put in the singular, to agree with one item ("channels" → "channel"; "are" → "is"); an item's own words stay as written ("oceans"). An item that names no specific thing ("his team") gives no ground truth triple (rule 9 of *What counts as a fact*: "Not a fact without a specific thing"). *Suppose:* a record says the SST is "derived from the long wave IR 11 and 12 micron wavelength channels". *Then:* two ground truth triples, with the objects "long wave IR 11 micron wavelength channel" and "long wave IR 12 micron wavelength channel". *Suppose:* a record says Aqua was launched "to study the global dynamics of the Earth atmosphere, land and oceans". *Then:* rule 19 first gives Aqua HAS_TARGET "Earth"; then three ground truth triples: Aqua HAS_PURPOSE "study the global dynamics of the atmosphere", "study the global dynamics of the land", and "study the global dynamics of the oceans". "global" stays in each: taking it out would give Aqua HAS_SPATIAL_COVERAGE "global", which isn't true, since Aqua is not data (rule 19, *What stays in the instance*).
    - **A period of time or a range of values is one instance, however it is worded** ("between A and B", "from A to B", "A to B", "A–B", "A through B", "A until B"). When other words come between its start and end, write the start and end joined by the record's own linking words, leaving the words in between out. *Suppose:* a record says "between 2014-11-19 and 2015-03-10". *Then:* one ground truth triple, with the object "between 2014-11-19 and 2015-03-10". *Suppose:* a record says "from January, 2007, through cruise, approach to and encounter with comet 9P/Tempel 1, and up to end of mission in March, 2011". *Then:* HAS_TIME_SPAN "from January, 2007 up to March, 2011".
    - **Lists joined by "/" or "+".** Split such a list only when the record's text also names its items separately somewhere else; otherwise keep it whole, as written. *Suppose:* a record says "Level 2/3 (EDR/RDR) data" and later "The RDR data convert the EDR (raw) sensor data". *Then:* the items are named separately, so the list splits. *Suppose:* a title says "RSI 1/2/3" and the record never names "RSI 1", "RSI 2" or "RSI 3" alone. *Then:* it stays whole. Lists joined by "and" or commas split as above.
    - **A list with an abbreviation of its own.** A list that the record gives one abbreviation of its own is a name, kept whole, only when the abbreviation stands for one thing; when it stands for several things, it is a list, and the abbreviation belongs to no item. *Suppose:* a record says "the U.S. National Aeronautics and Space Administration (NASA)" and "Land Surface Temperature and Emissivity (LST&E)". *Then:* "NASA" stands for one agency, so "National Aeronautics and Space Administration (NASA)" stays whole; "LST&E" stands for two quantities, a temperature and an emissivity, so the list splits into "Land Surface Temperature" and "Land Surface Emissivity", without "(LST&E)".
    - **Describing words joined by "and" or a comma.** Ask whether one of the things the words describe (one orbit, one balloon, one access) can have all the describing words at once. 1. Yes: keep them whole, in one ground truth triple. 2. No: split them, one ground truth triple per describing word. *Suppose:* a record says Aqua was launched "into a sun synchronous, polar orbit". *Then:* one orbit can be sun synchronous and polar at once, so one ground truth triple: Aqua HAS_ORBIT "sun synchronous, polar orbit". *Suppose:* a record says "over 50 small, approximately 20 kg, stratospheric balloons were successively launched". *Then:* one balloon can be small, approximately 20 kg and stratospheric at once, so one ground truth triple keeps the count whole: "over 50 small, approximately 20 kg, stratospheric balloons". *Suppose:* a record says a tool is meant "to access NASA technical information quickly and conveniently". *Then:* one access can be quick and convenient at once, so one ground truth triple keeps the whole phrase. *Suppose:* a record says the SST is "derived from the 11 and 12 micron channels". *Then:* one channel can't be both 11 micron and 12 micron, so two ground truth triples.
    - **Exception: a collective "and".** A distributive "and" means "A, and also B": what the record says holds for each item alone, so the list is split. A collective "and" means "A and B together": what the record says holds only for the items together (how they relate to each other, or something they make jointly); keep such a list whole, in one ground truth triple. Typical signs are a noun the list belongs to, such as "continuity of …", "ratio of …", "difference between …", "comparison of …", "correlation of …", "average of …", "merger of …". A word that is part of a name ("Normalized Difference Snow Index") is not a sign, and an adjective ("combined") or a preposition alone ("between") does not make an "and" collective (a period of time or a range of values is one instance; see above). If what the record says is true of each item alone, the "and" is distributive. The parts of one method (its passes, steps or settings), joined by "and" inside the method's words, are a collective "and": the method is made of them jointly, and no part alone was applied as a method (rule 24, *Input or method*). "both" is not a sign either way. *Suppose:* a record says the coefficients "are computed from the HIRDLS Level 2 profiles with a Kalman filter approach using both forward and backward passes in time". *Then:* the passes are parts of one method, so one ground truth triple: PRODUCED_USING_ALGORITHM "Kalman filter using both forward and backward passes in time" (rule 23 leaves out "approach", a type word). *Suppose:* a record says an algorithm is "intended to provide continuity of SST derived from heritage and current NASA sensors". *Then:* the list "heritage and current NASA sensors" follows "continuity of", so one ground truth triple keeps the whole phrase: the algorithm HAS_PURPOSE "provide continuity of SST derived from heritage and current NASA sensors". *Suppose:* a record's dataset is "Combined Terra and Aqua". *Then:* "combined" is an adjective, not a sign of a collective "and", and what the record says is true of each platform alone, so the list splits: the record's dataset FROM_PLATFORM "Terra" and FROM_PLATFORM "Aqua", since the data come from each platform.
23. **One thing, one wording, within a record.** When a record names the same thing more than once, in different words, use the wording the first of the four tests below picks, in every ground truth triple; the other wordings appear only in an ALSO_KNOWN_AS triple, and only if the record states one (rule 20). 1. The wording that says more: it contains the other's words, each as a whole word, is more precise, or spells out the other's abbreviation. 2. Otherwise, the wording from a sentence that states a fact about the thing with words for its predicate, rather than one that names it only by a title's or a name's words (rule 17, *A title's facts*, *A name's facts*). 3. Otherwise, the wording the record uses most often. 4. Otherwise, the wording the record gives first. *Suppose:* a record says "generated by the NASA Ocean Biology Processing Group (OBPG)", and later "JPL acquires data from the OBPG". *Then:* both ground truth triples use "NASA Ocean Biology Processing Group (OBPG)" for their instances (test 1: it spells out the abbreviation). *Suppose:* a title says "4km" and the notes say "4.63 km". *Then:* "4.63 km", the more precise (test 1). *Suppose:* a title says "OPERA Dynamic Surface Water Extent from Sentinel-1", and the notes say "DSWx-S1 provides near-global geographical mapping of surface water extent over land". *Then:* neither wording contains the other, and only the notes' sentence states the measurement with words for it ("provides … mapping of"), so the record's dataset HAS_MEASUREMENTS_OF "surface water extent over land" (test 2). To see that two wordings name the same thing, use clues anywhere in the record and what you know about the words (e.g. what an abbreviation stands for: MODIS is the Moderate Resolution Imaging Spectroradiometer; MID-IR is mid-infrared).
    - **The thing the title names.** The thing the title names (the describes triple's object instance) is the exception: it is always written as its title (rule 12).
    - **Type words.** 1. If the record writes a type word in lowercase beside the name at least once, outside text typed all in capitals, it is a type word everywhere in the record, even where it is capitalized. Leave out a type word that only describes the thing, written in lowercase beside the name: write "Aqua", not "Aqua satellite", since its entity class, Platform, already says what it is (rule 4 of *What counts as a fact*). Keep the type word only when the words left once it is removed aren't a name: write "GRaND plus Z boron loaded sensor", not "GRaND plus Z boron loaded". 2. Otherwise, the type word is part of the name, capitalized wherever the record writes it: keep it, and write "Hurricane Katrina", not "Katrina". *Suppose:* a record says "The BARREL Mission was a multiple-balloon investigation" and later "the BARREL mission launched only balloons". *Then:* the lowercase "mission" shows that the record uses it as a type word, so every ground truth triple writes "BARREL" (Mission). The type words of a method include "approach", "method", "technique", "procedure" and "algorithm". *Suppose:* a record says "with a Kalman filter approach", and another says "using a modified nonlinear SST algorithm". *Then:* "Kalman filter" is a name, so "approach" is left out; "modified nonlinear SST" isn't a name, so "modified nonlinear SST algorithm" stays whole.
    - **Capitals and punctuation.** A wording that differs only in capitals, spaces, hyphens or punctuation is the same wording, not a second one. 1. Write the wording as it appears where the record isn't typed all in capitals (usually the notes); if it appears there more than once, in the form used most often (on a tie, the first): "Vesta", not the all-capitals title's "VESTA". 2. Otherwise (the wording appears only in all capitals), write it as written. A leading "a", "an" or "the" is left out: write "series of screens", not "a series of screens". (These sentences are only in these guidelines, not in the model's copy of the rules: the evaluation ignores capitals, spacing, punctuation, dashes and a leading "a", "an" or "the" when pairing, so they change no score, and the model has fewer rules to follow.)
24. **A processing step: output = method(input).** For each processing step the record describes, find what it made (the output), what it was made from (the input), and how (the method). Each step gives up to two ground truth triples, each written only if the record names both of its ends: output COMPUTED_FROM input, and output PRODUCED_USING_ALGORITHM method. The words for the input and the method are then not part of another instance (rule 11). They are taken out only of the words for what the step made; a name that contains them stays whole (rule 11). *Suppose:* a record's notes describe its dataset as a "Multi-Angle Implementation of Atmospheric Correction (MAIAC) Land Aerosol Optical Depth gridded Level 2 product", used to calculate "the MAIAC Land Surface Bidirectional Reflectance Factor (BRF)". *Then:* the first words describe the record's dataset, whose name is its title (rule 23, *The thing the title names*), so the method is taken out: the record's dataset PRODUCED_USING_ALGORITHM "Multi-Angle Implementation of Atmospheric Correction (MAIAC)" and HAS_MEASUREMENTS_OF "Aerosol Optical Depth" ("Land" is taken out by rule 19). The second is the name of another product, made from the record's dataset, so "MAIAC Land Surface Bidirectional Reflectance Factor (BRF)" stays whole.
    - **One step after another.** One step's output can be the next step's input. *Suppose:* a record says its dataset holds "snow cover detected from the NDSI using a series of screens", and that "the NDSI is derived from radiance data". *Then:* two steps. Step 1: NDSI = ?(radiance data); the method isn't named, so only "NDSI" COMPUTED_FROM "radiance data". Step 2: the record's dataset = series of screens(NDSI); this gives the record's dataset COMPUTED_FROM "NDSI", and the record's dataset PRODUCED_USING_ALGORITHM "series of screens" (rule 23: a leading "a" is left out). The record's dataset HAS_MEASUREMENTS_OF "snow cover", without the words for the input and the method.
    - **Words that name no method.** A method is named by a noun or a name in the method's place of output = method(input): the record says the output was made by it, is stored as it, or is given by it ("4 s accumulations of counts", "Average daily … products", "given by the root-mean square of the differences", "using a modified nonlinear SST algorithm"). 1. Such a noun or name gives output PRODUCED_USING_ALGORITHM method, as written. 2. A verb or participle that says only that something was done to the data ("corrected", "calibrated", "detrended", "binned", "mapped", "edited", "convert", "weighted") names no method: it gives no ground truth triple, and stays in the instance, as written (rule 19: "A qualifier stays in the instance, as written, if it is any other kind"). 3. A noun for a statistic that names a stored field, not how the output was made ("Expressed as the mean and up to 7 sine and cosine coefficients"), is a Variable, not a method. *Suppose:* a record says "The rate count values are stored as 4 s accumulations of counts" and "The nominal fast neutron count rates were detrended using the GRaND epithermal neutron map". *Then:* the first gives the record's dataset PRODUCED_USING_ALGORITHM "accumulations" (and HAS_COMPOSITING_PERIOD "4 s", rule 18); the second gives "detrended" no ground truth triple, and the map's product COMPUTED_FROM "GRaND epithermal neutron map". *Suppose:* a record says "The dataset's radiances were calibrated, then cloud-cleared using the CCR algorithm." *Then:* the record's dataset PRODUCED_USING_ALGORITHM "CCR"; "calibrated" names no method, so it gives no triple. *Suppose:* a record says its dataset holds "calibrated radiances". *Then:* the record's dataset HAS_MEASUREMENTS_OF "calibrated radiances". What a step removed from the data, or corrected in them, is neither the step's input nor its method: the step's output CLEANED_OF it, when the record names it, and the record's words also stay in the instance, as written. *Suppose:* a record says "Some noise lines during the planetary encounters have been edited from the data set." *Then:* the record's dataset CLEANED_OF "noise lines during the planetary encounters". *Suppose:* a record says its dataset holds "solar stray-light corrected … image data". *Then:* the record's dataset CLEANED_OF "solar stray-light", and the image data keep the words "solar stray-light corrected".
    - **Input or method.** A method is what could be applied again to other data (an algorithm, a procedure, and its settings, such as coefficients tuned per month); an input is the data the step was applied to, which its output is made from. The test is the W3C sensor ontology's (SOSA/SSN): a procedure "is re-usable, and might be involved in many Observations", and an input is "information that is provided to a Procedure for its use". The statistics the CF Conventions' cell_methods name (sum or accumulation, mean, maximum, minimum, median, mode, range, standard deviation, variance, root mean square; CF 1.11, Appendix E) are methods in this sense. *Suppose:* a record says "The NDSI is derived from radiance data". *Then:* "radiance data" is an input, since the NDSI is made from them and they are not applied to other data: "NDSI" COMPUTED_FROM "radiance data". "Multi-Angle Implementation of Atmospheric Correction (MAIAC)", in this rule's first example, is a method: it is applied again to other data. An amount of data ("16 days of data", "3 years of observations") says how much data, not which: the amount is a number with its unit (rule 18), and the rest is an input only if it names data beyond the word "data". *Suppose:* a record says its product "is produced daily using 16 days of data". *Then:* the record's dataset HAS_TEMPORAL_RESOLUTION "daily" and HAS_COMPOSITING_PERIOD "16 days", and no COMPUTED_FROM.

### Examples

*Two facts in one sentence, and an opinion word.* *Suppose:* a record's text says "The NASA Technical Standards Program provides access to NASA developed standards and handbooks. … The idea is to make it simpler for technical people to access great NASA technical information quickly and conveniently." *Then:* "standards and handbooks" are two things, so two ground truth triples: "NASA Technical Standards Program" (Organization) PROVIDES_ACCESS_TO_DOCUMENT "NASA developed standards" (Document), and the same with "NASA developed handbooks". The purpose is one [ground truth triple](../docs/terminology.md#4-ground-truth-and-samples), "make it simpler for technical people to access NASA technical information quickly and conveniently" (rule 22: "quickly and conveniently" describe one action), written without "great". (From `annotations/ground_truth/batch_000.csv`, record `3122be4c-b9d0-4cc9-b6d3-9b96c6e743da`.)

## The describes triple

Every record has one [classed triple](../docs/terminology.md#2-triples) that no text states, written by code: the record's id DESCRIBES its title. Your only part in it is its [entity class](../docs/terminology.md#3-schemas), the [describes class](../docs/terminology.md#2-triples): the describes triple's [object class](../docs/terminology.md#2-triples) (e.g. Dataset, WebTool). Choose it in the tool's field *Object's entity class* of the [describes triple](../docs/terminology.md#2-triples). `X` means none is chosen yet.

## Coining an entity class or predicate

- **Coin one only when none of the [ground truth schema](../docs/terminology.md#3-schemas)'s fits.** Check the tool's list as you type, and **Help → Ground truth schema** (in the record's strip), which shows every one at a glance: a near-synonym may already exist.
- **Spell it in the ground truth schema's style:** an [entity class](../docs/terminology.md#3-schemas) in CamelCase (`SpaceMission`), a predicate in UPPER_SNAKE_CASE (`PART_OF_MISSION`), one word each.
- **Mark a new entity class for rule 19:** a line `rule 19: standalone` or `rule 19: describing` under it in `annotations/ground_truth_schema.txt` (rule 19 of *Writing a classed triple*, *Whose fact it is*). The tool doesn't add it; the tests name every entity class without one.
- **Give it a one-line definition at once:** press the button under its ✖, in the tool. Until then the model sees it without a definition, the tool marks it ✖, and step 070 won't evaluate a [finished record](../docs/terminology.md#4-ground-truth-and-samples) that uses it.
- **To rename one, or merge two that mean the same thing:** the tool's **Help → Ground truth schema**, then **Edit definitions, rename, or merge…**, then **[Rename or merge…](../docs/terminology.md#3-schemas)** (`annotations/README.md`, *The ground truth schema*).

## Finishing a record

- **Tick *All facts extracted*** only when every fact the record states is there. Only [finished records](../docs/terminology.md#4-ground-truth-and-samples) are extracted (step 060) and evaluated (step 070). The tool lets it be ticked only once no row of the record has a ✖ (step 070 won't evaluate a finished record with one).
- **A record that states no facts:** delete every [ground truth triple](../docs/terminology.md#4-ground-truth-and-samples) of the record; the tool then keeps one row of the file with only the record's id, which means "annotated, states no facts". Still tick *All facts extracted*.
- **Fix what the tool marks:** ✖ must be fixed (e.g. a [source text](../docs/terminology.md#1-records-and-their-text) that isn't in the record's text); ⚑ is worth a look (e.g. a [subject instance](../docs/terminology.md#2-triples) that isn't in the text, which may be a typo or a deliberate rewording).
- **A record that contradicts itself** (two passages disagree about one fact, such as a title that names one spacecraft and notes about another body): write what each passage states (rule 1 of *What counts as a fact*), and correct neither from outside knowledge. Add an item to `annotations/left_out.md` that quotes both passages, so that the conflict can be reported to the record's maintainer. *Suppose:* a record is titled "Solar Orbiter Ephemeris, …", and its notes say "Heliocentric trajectories for Comet Borrelly". *Then:* [the record's dataset](../docs/terminology.md#1-records-and-their-text) HAS_VARIABLE "Solar Orbiter Ephemeris" and HAS_TARGET "Comet Borrelly", and an item of `annotations/left_out.md` quotes both.
- **If a ground truth triple isn't connected to the record's id through the others,** look for the fact that connects the [triple](../docs/terminology.md#2-triples), and add that fact only if the record states it. The tool marks such triples ⚑.
- **Commit the file to Git** (`annotations/ground_truth/batch_<NNN>.csv`).
