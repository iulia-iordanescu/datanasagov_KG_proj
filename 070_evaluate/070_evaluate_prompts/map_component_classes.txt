Two vocabularies each have component classes of two kinds: entity classes
(kinds of things) and predicates (kinds of relationships). GROUND_TRUTH is the
ground truth schema, grouped by kind; SCHEMA lists component classes of
the current schema, each with its "kind". Every entry gives a
"component_class" and its "definition".

For each component class in SCHEMA, give the component class in
GROUND_TRUTH, of the same kind, that means the same thing. If none of
GROUND_TRUTH does, give the one for its main meaning, when one meaning
clearly dominates; a component class of GROUND_TRUTH broader than it counts.
Give null when its meaning splits between several component classes of
GROUND_TRUTH, or when none of GROUND_TRUTH has its meaning. Judge by meaning
and definition, not by spelling.

For a predicate, set "reversed": true when the predicate in GROUND_TRUTH
states the same relationship in the opposite direction ("A CARRIES B" means
"B ABOARD A"); otherwise false.

Use only component classes exactly as they are written in GROUND_TRUTH.
Several component classes of SCHEMA may map to the same component class of
GROUND_TRUTH. Answer for every component class of SCHEMA.

REPLY FORMAT

Return only JSON, with no prose. In each entry, "kind" is "entity class" or
"predicate", "schema" is the component class from SCHEMA, "ground_truth" is
the one from GROUND_TRUTH (null when there is none), and "reversed" is true
or false:
{"mapping": [{"kind": "<kind>", "schema": "<component class>", "ground_truth": "<component class>", "reversed": false}]}

GROUND_TRUTH
$ground_truth

SCHEMA
$schema
