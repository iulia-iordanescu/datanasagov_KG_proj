Two vocabularies each have component classes of two kinds: entity classes
(kinds of things) and predicates (kinds of relationships). GROUND_TRUTH lists
component classes of the ground truth schema, grouped by kind; SCHEMA
lists component classes of the current schema, each with its "kind". Every
entry gives a "component_class" and its "definition".

The component classes in SCHEMA were each judged earlier to have no
counterpart in the ground truth schema, which has since gained component
classes. GROUND_TRUTH holds those of its component classes that nothing is
matched to yet. For each component class in
SCHEMA, say whether a component class in GROUND_TRUTH, of the same kind,
means the same thing. If none of GROUND_TRUTH does, say whether one is for
its main meaning, when one meaning clearly dominates; a component class of
GROUND_TRUTH broader than it counts. Suggest nothing for it when its meaning
splits between several component classes of GROUND_TRUTH. Judge by meaning
and definition, not by spelling.
Suggest a pair only if you are confident; leave a component class out
otherwise.

Use only component classes exactly as they are written in the two lists.

REPLY FORMAT

Return only JSON, with no prose. In each entry, "kind" is "entity class" or
"predicate", "schema" is the component class from SCHEMA, and
"ground_truth" is the one from GROUND_TRUTH:
{"suggestions": [{"kind": "<kind>", "schema": "<component class>", "ground_truth": "<component class>"}]}
Return {"suggestions": []} if you are confident of none.
