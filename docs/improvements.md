# Improvements list

The changes to make to the pipeline itself: what to change, why, and where the idea came from. Not to be confused with the upkeep (`upkeep.md`): what a person running the pipeline does, and when. An item that is done is deleted here, and the commit that does it says so. Measured results that an item rests on are in [`findings.md`](findings.md).

## The whole pipeline

- **Repeat runs, to measure run-to-run noise.** A setting that skips the saved answers, so that a step can be run again with exactly the same settings. One run isn't a baseline: two runs of step 040 with the same settings, differing only by one rule of the prompt (rule 8), spelled 41 of the 63 entity classes and 67 of the 126 predicates the same. From: [`findings.md`](findings.md), 2026-10-12.
- **Cost per run.** Each report already gives the tokens sent and received (section *Model calls*); a price per token would turn them into dollars. From: the literature review of 2026-10-07.
- **A batch API at NASA's LiteLLM**, if it has one: many calls sent together, at a discount. Ask NASA's LiteLLM administrators. From: 2026-10-13.
- **Saved answers that are JSON of the wrong shape.** An answer that is JSON is saved whatever its shape (`common/common_helpers/cache.py`, `ask_cached`), so a rerun reuses a useless one instead of asking again. Check the shape before saving. From: 2026-10-12.
- **Keep the saved answers safe:** every model answer behind a reported number is in the steps' `cache/` folders under `outputs/`, which Git doesn't carry, so they exist only on the computer that ran the step. Archive them with each run that numbers are reported from. From: the methods review of 2026-10-11, item 7.
- **`tests/run_all.py` on the NASA laptop:** its first run there reported that the tests changed files, and the next run passed. Find why. From: 2026-10-12.
- **README, *How to reproduce*:** setup and running are in [`running_on_nasa_laptop.md`](running_on_nasa_laptop.md); building the graph waits for step 080. From: my old to-do list.
- **Other catalogs:** some things fit only data.nasa.gov. The catalog's address is fixed in the code (`010_harvest/010_harvest_helpers/ckan_client.py`); "undefined" is treated as a maintainer (`020_clean/020_clean_helpers/maintainers.py`); splitting into strata needs a maintainer field that other catalogs may not fill; step 040's prompts say "a catalog of NASA datasets". From: the methods review of 2026-10-11, item 11.
- **Competency questions:** 10 to 20 questions the knowledge graph should answer, to judge it by. From: the literature review of 2026-10-07.

## 040_induce_schema

- **The sample of texts:** 10 maintainers × 15 texts is the documented baseline, not a design shown to be best. Taking only the 10 largest maintainers, it can never sample the records of the others (about 8% of the catalog, on the 2026-09-27 harvest; the methods review of 2026-10-11, item 3). Compare designs with `helpers/compare_runs.py`, guided by the saturation curve in 040's report. From: [`findings.md`](findings.md), 2026-10-12.
- **`min_support`** above 1 (it is 1, which keeps everything found): try other values once runs can be compared. From: 040's guide, *Settings*.
- **Near-duplicate texts inflate support.** If a maintainer's 15 texts are nearly the same text, every schema entry found in them counts 15 times. Measure how alike each maintainer's texts are; then drop the near-duplicates (taking others from the same maintainer), or count that maintainer once. It matters once `min_support` is above 1. 040's report lists twins between the texts it learned from and the pool, not near-duplicates among its own texts. From: my old to-do list.
- **Nothing filters junk from stage 2:** e.g. "dataset" as a bare subject instance, or "VNP43D66 is the BSA" read as an "is a" statement, both gaining real support. A list of generic subject instances to drop would cost nothing. From: my old to-do list.
- **Alternatives to stage 4 (merging synonymous labels):** grouping by similarity, passing the chosen labels forward from batch to batch, or another approach entirely. From: my old to-do list.
- **Which text fields to learn from:** 040 uses `title` and `notes` and any field 020's `extra_text_fields` adds; which other fields help is untested. First candidate: the names of the files attached to a record (e.g. `…L3m.8D.SST4…nc`), which can say what a data set holds when its notes describe several (2026-10-19, record #4). From: my old to-do list.
- **Ideas to compare the induced schema with:** the Purview glossary, Neo4j's capabilities, the five science domains of NASA's Science Mission Directorate (SMD) site, and the filters data.nasa.gov's search offers. From: my old to-do list.

## 060_extract

- **Patterns in or out of the prompt:** patterns are 58% of the schema text (about 14,500 tokens in all). Compare runs with and without them. From: [`findings.md`](findings.md), 2026-10-12.
- **Experiment: the source text first in the model's answer.** The reply asks for subject, predicate, object, and their entity classes, then the source text last, so the model states a fact and finds its passage afterwards. Asking for the passage first, then the fact, may give facts that keep closer to the text. A model that thinks before answering (claude-opus-5.5 does) may gain less. From: Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), section 14.7.1.
- **An entity class or predicate that does badly:** try renaming it first (a generic entity class or predicate gave unstable results there; a more specific one fixed it). From: Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), section 5.3.3.
- **Prompt size and cost:** measure both on the first run. From: 2026-10-12.
- **The content filter:** in step 040 the service refused phrases from GeneLab (space biology) records. Watch whether 060's failed records cluster there. From: [`findings.md`](findings.md), 2026-10-12.
- **A fixed schema for the full run,** chosen and kept in Git, so that the full run doesn't depend on whatever `outputs/` holds. From: 2026-10-12.

## 070_evaluate

- **Raise With Mentors: checking a sample of the occurrences left extracted only,** to see how far precision and recall are understated ([`metrics/pairs.md`](../070_evaluate/metrics/pairs.md), *The same fact in different words*). It's an involved process: such an occurrence can be the same fact in different words as a ground truth triple left ground truth only, a repeat of a fact already paired, a fact the ground truth lacks, the result of a wrong translation, or actually wrong, and each means something different. From: 070's guide, *To do*.
- **About 10 records annotated from scratch,** with no drafted triples: measures how far drafted triples steer annotation (recall may be overstated by a model-drafted ground truth: [`metrics/recall.md`](../070_evaluate/metrics/recall.md)). From: the literature review of 2026-10-07.
- **A second annotator** for a sample of records, to measure agreement between people (Hripcsak & Rothschild 2005). From: the literature review of 2026-10-07.
- **A second person checking a sample of the translation table,** frozen before the held-out part is looked at. From: the literature review of 2026-10-07.
- **How many classed triples 060 removed, per reason,** in 070's report. From: the literature review of 2026-10-07.
- **Precision and recall per predicate and per entity class,** to see which ones extraction gets wrong (070 gives them per part and per stratum only). From: Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), section 5.3.3.
- **Other quality metrics,** e.g. coverage. 070 already reports partial pairs, entity-class accuracy, and the recall upper bound. From: my old to-do list.
- **The model's run-to-run variation** isn't among the reasons the numbers are approximate ([`metrics/approximately.md`](../070_evaluate/metrics/approximately.md)), and margins of error leave it out. Add it once repeat runs measure it (see *The whole pipeline*). From: the methods review of 2026-10-11, item 6.
- **Comparing runs whose schemas differ:** several component classes of a schema may translate to one of the ground truth schema, so a finer schema is forgiven some wrong entity classes ([`metrics/pairs.md`](../070_evaluate/metrics/pairs.md), row 5 of *When a pair isn't the same fact*). `helpers/compare_runs.py` should say so when the runs' schemas differ. From: the methods review of 2026-10-11, item 10.
- **The 10-point threshold** of 070's warning that a stratum's share of the evaluated records differs from its share of the pool: no source for 10. From: the literature review of 2026-10-07.
- **Citations not yet checked:** Cochran (1977) for the 5% rule and the ratio bias, cited from memory in the metric docs. From: the literature review of 2026-10-07.
- **Report wording:** "share" where "proportion" is meant (070's guide, `070_evaluate_helpers/readings.py`), and "extracted triple(s)" where an occurrence is meant (070's report). From: 2026-10-08.
- **The partial-pair verdicts in the recipe:** `helpers/compare_runs.py` compares two runs of 070 on records with the same ground truth, but a verdict changed between the runs (`annotations/partial_pair_reviews.csv`) also changes the numbers, and neither the recipe nor the ground truth's fingerprint holds the verdicts. Fingerprint each record's verdicts with its ground truth, so such a record is left out and named. From: the project sweep of 2026-10-14.
- **Stop on a coined component class before asking to go ahead:** 070 checks the finished records for entity classes and predicates not in the ground truth schema in stage 2, after stage 1 has shown its warnings and asked whether to go ahead; nothing is paid before the stop, but checking in stage 1, with the other ground truth problems, would stop sooner. From: the project sweep of 2026-10-14.
- **Twins and "evened out":** 070 finds twins by comparing `title` and `notes` fields with case, spacing, quote marks, and dashes ignored (`common/common_helpers/ground_truth.py`), while the term *evened out* (`docs/terminology.md`) also ignores edge punctuation and a leading "a", "an", or "the". Decide which the twins should use, and make the guide and the code say the same. From: the project sweep of 2026-10-14.

## 080_build_graph

- **Before designing 080, read the rest of** Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026): chapter 3 (RDF or a labeled property graph), chapter 4 (combining several sources: phase 1's graph and phase 2's triples), and chapters 13 and 14 (how people ask questions of a finished graph, for the competency questions). Chapters 5 to 8 and part of 14 were read on 2026-10-14 (the items here citing the book). From: 2026-10-14.
- **Three layers:** the records; each extracted triple as extracted (never joined with another), with its record and source text; and the knowledge graph built from those. The knowledge graph can then be rebuilt without asking a model again, and every edge can show the passage it came from. From: Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), section 6.1.
- **A layer of facts from the model's own knowledge:** joining names ("MODIS" = "Moderate-resolution Imaging Spectroradiometer (MODIS)"), reading codes ("MID-IR" in a title meaning SST4), and background facts, each marked as the model's, kept apart from the extracted triples (which stay what the record states), and checked by a person on a sample, with its own accuracy. From: 2026-10-19.
- **A record's node: `Dataset` or `CatalogEntry`?** Phase 1's graph makes each record a node labeled `Dataset`, while the describes triple gives the record the entity class `CatalogEntry` and gives `Dataset` (or `WebTool`, …) to what its title names. Decide which the graph uses before building it. From: the terminology sweep of 2026-10-15.
- **Linking subject instances and object instances to reference lists,** so that one thing named several ways ("Aqua", "EOS PM-1") becomes one node. First processing levels, a short fixed list (L0, L1A, L1B, L2, L3, L4: every spelling, such as "Level 3" or "L-3", mapped to one); then NASA's missions ([A to Z of NASA missions](https://www.nasa.gov/a-to-z-of-nasa-missions/)), where a subject or object instance with no match is marked for a person to check, not dropped, since the catalog also names missions of other agencies; GCMD keywords as another list. How: the subject or object instance keeps the record's words and gets an edge to its entry, saying how the match was made; candidates come from the list, never from a model (exact match after evening out, "Long Name (ACRONYM)" split into both forms, then near spellings as candidates only); a model chooses only among two or more candidates, and may answer "none of these"; a small hand-checked set of subject or object instance → entry (or none) measures it. Aliases ("EOS PM-1" for Aqua) must be written for our lists. From: my old to-do list; 2026-10-13; Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), chapters 7 and 8 (which choose without a "none" answer and don't measure linking).
- **Which predicates give properties instead of edges,** by the rule of README, *Phase 1*: a processing level, for example, has few values, which people filter by but don't go from node to node through. From: my old to-do list; 2026-10-13.
- **Splitting a number with a unit** ("250 m") into a value and a unit, as graphs store quantities (Wikidata, QUDT, schema.org's QuantitativeValue). From: 2026-10-11.
- **A fact many records state:** one edge per extracted triple, or one edge listing the records it came from. Either way, keep which records each edge came from. From: 2026-10-06.
- **Joining subject instances and object instances that name the same thing into one node** beyond the lists: similar spelling plus shared neighbors (two spacecraft names spelled alike that carry the same instrument), grouped into connected components, the longest name kept; generic words ("Data", "Product", "Level") never count as similar. From: Negro, Futia, Kůs, and Montagna, *Knowledge Graphs and LLMs in Action* (Manning, 2026), section 6.1.4.
- **Checks of the graph:** how well nodes were joined (precision and recall of the joining), duplicate nodes, and a person checking a sample of edges. From: the literature review of 2026-10-07.
- **Phase 1's maintainers:** README's table says 434 Maintainer nodes, but 020 joins maintainer spellings down to 422. Rebuild phase 1's part with 020's cleaning. From: my old to-do list.
- **More edges from the metadata fields other than the text fields** (phase 1): fields not used yet may give more edges, or properties. From: my old to-do list.
