The rules are numbered as in the annotation guidelines that a person
follows. The words for predicates and entity classes in these rules and
their examples ("computed from", "aboard", "an instrument") say what a fact
means; in your answer, use the predicate names and entity class names that
the task above says to use.

HOW THE RULES USE THEIR WORDS

Each wording below has one meaning in every rule.

- Entity. An entity is one individual that an instance's words refer to,
  such as Kestrel. Many entities share one entity class: Kestrel, Osprey,
  and Tern are three entities of the entity class instrument. One entity may
  be named in a record by several wordings, such as "Kestrel" and "Kestrel
  Lake Ice Radiometer (Kestrel)", which rule 23 (one wording) writes as one
  instance.
- Instance, subject instance, object instance. An instance is the record's
  words for one entity, as rule 11 (the record's own words) and rule 23 (one
  wording) write them, in the subject slot of a triple (its subject
  instance) or in its object slot (its object instance). An instance is
  words; the entity is what they refer to.
- Name. A name is the record's words for one entity. A name is an instance
  only when it is the subject instance or the object instance of a triple:
  "QX7" in "QX7 Wide Field Camera" is a name, and it is no instance when the
  record never says what QX7 is (rule 1, only what the record states).
- Entity class. An entity class is a type of entity, such as an instrument
  or a platform. Each subject instance and each object instance has the
  entity class of the entity it refers to.
- Predicate. A predicate is the relationship that a triple states between
  its subject instance and its object instance, such as "collected by" or
  "aboard".
- Triple. A fact that the record states, written as a subject instance with
  its entity class, a predicate, and an object instance with its entity
  class.
- Qualifier, word. A qualifier is a word or phrase, in the record's words
  for a subject instance or an object instance, that narrows what the
  instance names ("daily" in "daily lake ice extent"). Rule 19 (qualifiers)
  decides what happens to a qualifier. The words that other rules decide
  about (opinion words, type words) are called words.
- Type word. A type word is a word beside a name that says what type of
  entity the name refers to ("satellite" in "the Halden satellite"). Rule 23
  (one wording), Type words, decides when a type word is taken out.
- Source text. The source text of a triple is the passage of the record that
  states it, copied exactly. Rule 17 (source text) gives its cases. In your
  answer, the source text is source_text.
- The title's instance, the record's dataset, another dataset. The title's
  instance is the record's title, written as an instance: the record's words
  for the entity that the record describes. Its entity class is the one you
  give as describes_class. The title's instance is called the record's
  dataset when it refers to a dataset. Every other dataset that the record
  names is another dataset.
- Standalone, describing. An entity class is standalone when its instances
  exist on their own and have facts of their own, such as a dataset, an
  organization, a person, an instrument, a platform, a mission phase, a
  variable or an algorithm. An entity class is describing when its instances
  only describe another entity, such as a measured quantity, a purpose, a
  task, a role or a time. Rule 19 (qualifiers), Whose fact it is, uses the
  two.
- Taken out, stays in the instance. A word that a rule takes out is not
  written in the instance. A word that is not taken out stays in the
  instance, as the record writes it. Whether a word that is taken out gives
  a triple of its own is a separate matter, which each rule decides: a
  qualifier that rule 19 takes out gives one, and an opinion word that rule
  5 takes out gives none.
- Stays whole. A name, a list or a phrase stays whole when it is written as
  one instance, with no word taken out, and is not split into several
  instances.
- Left out, gives no triple. A fact that a rule leaves out is not written as
  a triple, and the words that state it give no triple.
- States, says. The record states a fact when its own words assert it. "A
  record says" only introduces the record's words in an example.

WHAT COUNTS AS A FACT

1. Only what the record states. Never add what you know from elsewhere. An
   unexplained code or abbreviation gives no triple whose meaning depends on
   what it stands for, and what it stands for is never written, its entity
   class included, except as A name the record does not explain (below)
   allows. A code counts as explained when it follows one of these catalog
   conventions: "V" or "Version" followed by a number is a version ("V027");
   "L" or "Level" followed by a number is a processing level ("L2"). Any
   other code needs the record's own explanation. The list of conventions is
   closed. The record may be one part of a longer record ("part 1 of 2");
   state only what this part states. Rule 23 (one wording) gives the one
   other use of what you know: what words mean, to see that two wordings
   name the same entity.
   - A name the record does not explain. When the record never states what a
     name refers to, the name gets an entity class only as this part allows.
     You may give it an entity class from your own knowledge only when you
     are certain which entity class it belongs to. The entity class is never
     chosen from the verb that joins the name to another instance ("observed
     by", "onboard"). The entity class is all that this part gives: each
     triple must still be a fact the record states, and the name is written
     as the record writes it, never expanded into a long form that the
     record does not give. When the name gets no entity class, no triple
     whose meaning depends on what the name refers to is written, and the
     name may still stay inside a longer instance (rule 2, every fact, A
     fact inside a name). A name needs no outside knowledge in two cases. A
     name in the form of a personal name, one or more given names or
     initials followed by a surname ("R.T. Okafor"), is a person by its
     form. A name that contains a word saying what type of entity it refers
     to ("Radiometer" in "Halden Lake Ice Radiometer", "Group" in "Lake
     Mapping Group") is explained by the record's own words when that word
     fits the definition of exactly one entity class, since the word is the
     record's own.
     - Example: A title "KX12/Halden Lake Ice L3", whose notes never state
       what KX12 is, where you know KX12 as an instrument, gives the
       record's dataset collected by "KX12" (an instrument).
     - Example: "taken by the QX7 Wide Field Camera", in a record that never
       states what QX7 is, where you don't know QX7 either, gives no triple
       in which "QX7" is an instance, and "QX7 Wide Field Camera" stays
       whole.
   - A fact the record does not state. A fact that the record does not state
     may be written only when it follows from what the record states by one
     of the three tests below (Replacement, Comparison, Membership by name);
     nothing else, and no outside knowledge, adds such a fact. The list of
     tests is closed, as the list of conventions above is. The source text
     of such a fact is the passages that meet the test (rule 17, source
     text, Words in different places).
   - Replacement. When the record states that an older version or product is
     discontinued or decommissioned and directs users to a newer one, the
     newer one supersedes the older one.
     - Example: "Version 3 was decommissioned in 2019. Please use Version
       4." gives "Version 4" superseding "Version 3".
   - Comparison. When the record states that one entity it names is lower,
     higher, better (or any other comparison) without stating than what, and
     names exactly two entities of the same entity class together, the other
     of the two is what the first is compared with. When the record names
     three or more, no fact is written.
     - Example: "Two products are made, Q1 and Q2. Q2 has lower noise."
       gives Q2 having lower noise than Q1.
   - Membership by name. When the title or an identifier of the record's
     dataset contains the name of a group of datasets that the record
     describes, the record's dataset is a member of the group. A statement
     about the group is then written for the record's dataset only when it
     holds for each member alone: it says "all" or "each", or it gives a
     property that every member has (a version, a grid, access terms). A
     statement about the group as a whole is not written for the record's
     dataset: what the members cover taken together, "either … or", how many
     members there are.
     - Example: A record titled "TERN Lake Ice Daily L2" that says "all TERN
       data products are Release 4 files" and "TERN observations cover
       either the north or the south basin" gives the record's dataset the
       version "Release 4", and no triple for the basins.
2. Every fact the record states (the task above says which), unless a rule
   leaves it out: rule 1 (only what the record states), this rule's part A
   fact inside a name, rules 3 to 10, and rules 16, 20, 21, 22, 23 and 24
   (rule 22 for an item of a list that names no specific entity and for the
   abbreviation of a list of several entities, rule 23 for a type word). The
   title states facts too.
   - Example: "Kestrel/Halden Lake Ice 20-Min L2 Swath 800m V027", with
     notes that say "collected by Kestrel on the Halden satellite", gives,
     among others, the record's dataset collected by Kestrel and with a
     spatial resolution of "800m".
   - A fact inside a name. A fact counts wherever its words are, even inside
     a name. Every fact a name's words state is a triple, and every rule
     applies to it as to any other fact. The name itself stays whole (rule
     11, the record's own words), and the source text of the fact is the
     name as written (rule 17, source text, A name's facts). Rule 1 (only
     what the record states) decides what a name's words state, as it does
     for all other words. A word of a name that refers to another entity,
     with no words that say how the two entities are related, states a fact
     only when the naming itself states one. The test asks which predicate
     the name states. The predicate must be one that the naming itself
     states, which the entity classes of the two entities and the naming
     pattern (which of the two names stands inside the other's, and where)
     decide, and there must be exactly one such predicate that you may use.
     The name's words then state that predicate's fact. An instrument named
     in a dataset's name states that the dataset was collected by the
     instrument; a platform named in a dataset's name states that the
     dataset was collected from the platform; a mission named in a dataset's
     name states that the dataset was collected during the mission; a
     mission named in the name of one of its parts (an instrument, a craft,
     a campaign, a team) states that the part is a part of the mission; and
     an organization named before a group's own name states that the group
     is a part of the organization. Naming a unit with an organization's
     name before its own states that the unit belongs to that organization,
     and states neither sponsorship nor development. A relationship that
     naming does not state (that one entity funded, developed, provided or
     sponsored the other) is never read from a name, and is a fact only when
     the record has words that say so. When the naming states more than one
     predicate, or none, the name's words give no triple, since choosing one
     would add what the record does not state. The test decides only the
     facts that are read from a name's words. A fact that a sentence states
     with words of its own is a triple like any other fact (the task above
     says which facts to write).
     - Example: "The index is made from brightness data" gives "brightness
       data" holding measurements of "brightness", with the source text
       "brightness data", and "brightness data" stays whole.
     - Example: "produced by the Halden Office Lake Mapping Group", in a
       record that also says "funded by the Halden Office", gives "Halden
       Office Lake Mapping Group" part of "Halden Office".
     - Example: "made from Tern-2 radar scans", where Tern-2 is a satellite,
       gives "Tern-2 radar scans" collected from the platform "Tern-2";
       "contains modified Borealis data", where Borealis is a programme that
       an agency runs, gives no triple for "Borealis", since a programme's
       name before the data's could mean that the programme provided the
       data, funded them or collected them.
     - Example: "The file holds the Halden Orbit Table", with no words that
       say how the table and the satellite Halden are related, gives no
       triple for "Halden": a table of the satellite's orbit is not
       collected from the satellite, and naming states no other predicate.
3. Not the field names. The record's text is split into its text fields,
   each starting with its name ($field_names); the field names are
   formatting, not facts. A heading inside a text field, a line of its own
   that only names the passage below it ("Data Access"), is formatting too,
   and gives no triple.
4. Not "is a" facts. A sentence that says what type of entity an instance
   refers to ("Kestrel is an imager") gives no triple: the instance's entity
   class says it. A sentence that names one specific role is not an "is a"
   fact, though, and gives a triple ("X is the official … archive for Y"). A
   phrase that says what type of entity an instance refers to and also names
   another entity that it belongs to states two facts (rule 15, one fact per
   triple): the type is left out, and the belonging is a triple.
   - Example: "Chosen as a Halden Survey Pathfinder Project, TERN was built
     to ..." gives "TERN" part of "Halden Survey", and no triple for
     "Pathfinder Project".
5. Not opinions. Take out words such as "great".
   - Example: "browse great lake survey maps" gives the instance "lake
     survey maps".
6. Not negated facts. A triple can't say "not", and a negated fact is not
   rewritten into a fact the record doesn't state.
   - Example: "Data are not available before 1994" gives no triple.
7. Not facts the record doesn't assert as true: uncertain ones, and ones it
   requires, requests or recommends. "May", "might", "possibly", and "is
   expected to" when it means "will probably" make a fact uncertain.
   "Should", "are requested to", "are asked to", and "are expected to" when
   it means "must" make it a requirement, a request or a recommendation. A
   value given as approximate is stated, though ("approximately 350 m" is an
   object instance).
   - Example: "all users are expected to cite the TERN archive" gives no
     triple, since the record asks it of users and doesn't state that they
     do.
8. Not the values inside a data table; only what the table is about. For a
   table of values inside the record (rows of measurements, one per object),
   write what the table is about (what it measures, what it covers), and no
   triple per cell: the values are the record's dataset's own data, not
   facts about it.
   - A study a record tells. When a record tells the study its dataset comes
     from, the study's aim and its method are facts of the record's dataset
     (its purpose, and the method it was produced using, rule 24, a
     processing step). The rest of the study is not: its background, its
     findings, what it says about methods it did not use, and the details of
     its method beyond what rule 24 writes (how the method was applied, its
     parameters, what it allows). A finding is a result the study drew from
     the data, not what the data are, and the knowledge graph that the
     triples build is for finding the catalog's datasets.
     - Example: "The authors aimed to map the spread of lake algae, using a
       Kalman filter, which allows for gaps between the overpasses, and find
       that the algae spread fastest in June" gives the record's dataset the
       purpose "map the spread of lake algae" and produced using "Kalman
       filter", and no triple for what the filter allows or for the finding.
9. Not a fact without a specific entity. A triple needs a subject and an
   object the record names: "several wavelengths" names no wavelength.
   - Example: "Kestrel records data at several wavelengths" gives no triple.
   - A group named by a count or a common noun. A fact the record states for
     each member of a group it names only by a count or a common noun ("40
     channels each with …", "Each file is …") is written for the entity the
     group belongs to only when it stays true of that entity: what it holds,
     what it measures, what it comes from, or what format its files are in.
     An amount or a count per member gives no triple, unless the predicate
     itself says "each" (each file's period; each value's spatial
     resolution).
     - Example: "There are 40 channels, each with a gain and an offset"
       gives the record's dataset the supporting data "gain" and "offset".
     - Example: "300 lakes observed 3 to 9 times each" gives no triple for
       the times.
   - A word that only says how another fact holds. Such a word gives no
     triple, and is taken out of the instance: its subject would be that
     fact, not an entity the record names. By the test of rule 11 (the
     record's own words), such a word is sometimes not taken out. It is then
     part of what the predicate says when the object is an amount (rule 18,
     a number with a unit), and it stays in the instance otherwise.
     - Example: "the main target is Halden-4" gives the record's dataset's
       target "Halden-4", without "main" (a main target is a target);
       "developed jointly by the Kestrel Office and the Halden Office" gives
       the two developers, without "jointly".
     - Example: "the data's reliable depth range is 2 to 40 m" gives the
       record's dataset a range its values can be used over, "2 to 40 m",
       since the data may reach beyond it.
   - What data are used for. What data have been used for, or can be used
     for, is a fact of the work that used them, not of the data: when the
     record doesn't name that work, it gives no triple. A use that names
     what was made from the data gives that product's input (rule 21,
     general facts and other datasets).
     - Example: "The data have been used to study lake warming" gives no
       triple; "this dataset, A, is used to make dataset B" gives "B"
       computed from "A".
10. Not words that are true only as of when the record was written. Take out
    "latest", "current", "now", "then available", and words like them, and
    keep the rest of the fact.
    - Example: "The newest release, R4" gives the record's dataset's version
      "R4", without "newest", which stops being true once another release
      comes out.
    - Example: "E1 is the first edition" gives "E1" also known as "first
      edition", since E1 stays the first edition whatever is released later.

WRITING A TRIPLE

11. Subject instance and object instance: the record's own words, as
    written. Don't paraphrase them, and don't expand an abbreviation the
    record leaves unexpanded. The exceptions are the words that rules 5
    (opinions), 9 (a specific entity), 10 (words true only as of writing),
    19 (qualifiers), 20 (parentheses), 22 (lists), 23 (one wording) and 24
    (a processing step) take out. A word that rules 5, 9, 10 or 19 take out
    is not taken out when the record doesn't state the fact without it, that
    is, when the record's sentence doesn't imply the shorter one. A name
    stays whole: rules 19, 22 and 24 never split or shorten a name ("Kestrel
    and Halden Survey Office" keeps its "and"; "Earth Imaging Satellites
    (EIS)" keeps "Earth"). A fact that the name's words state is still a
    triple of its own (rule 2, every fact, A fact inside a name). One
    exception: a name made of the record's dataset's code and its version
    gives its parts as facts of their own, and a version so named is written
    as the version alone. The name of any other entity that holds a version
    stays whole ("version 2 Lake Archive Format (LAF2)", a file format, is
    one instance).
    - Example: "current" stays in "fed by older and current gauges", since
      it sets the newer gauges against the older ones.
    - Example: "Earth Imaging Satellites (EIS)" stays whole, and has the
      target body "Earth".
    - Example: "the KX12 Version 3 product" gives the record's dataset's
      identifier "KX12" and its version "Version 3".
12. The subject instance is what the sentence is about, which isn't always
    the title. A fact about the entity that the title names has the title's
    instance as its subject instance.
13. The predicate reads from subject to object. A triple whose subject
    instance is the record's dataset, whose predicate is "collected by", and
    whose object instance is "Kestrel" says that the dataset was collected
    by Kestrel, not that Kestrel was collected by the dataset.
14. Entity classes and predicates: use them as the task above says.
15. One fact per triple. A sentence that states two facts gives two triples.
    - Example: "The data were collected by Kestrel aboard Halden" gives two
      triples: the record's dataset collected by Kestrel, and Kestrel aboard
      Halden.
16. Each fact once, even if the record states it twice or in other words.
    Rule 23 (one wording) says which wording to use.
    - Example: "provides weekly lake ice extent" and later "the extent is
      mapped every week" state one fact, so one triple: the record's
      dataset's temporal resolution "weekly", the wording the record gives
      first.
17. Source text, copied exactly. 1. The shortest passage that contains words
    for the subject, the predicate and the object. 2. When the words for one
    of the three are only in another sentence, and no whole sentence lies
    between the two sentences, one passage from the earlier of the two (the
    fact, or the words for the missing one) to the end of the later.
    3. Otherwise, two passages joined by " … " (Words in different places,
    below). The words for the subject or the object are the instance as
    written, or the words of the fact's sentence that the rules write the
    instance from: the same words with a word among them that a rule takes
    out (rule 11), or an item of a list with the words that the items share
    (rule 22). An abbreviation alone, the name without its abbreviation, or
    any other wording shorter than the instance names the entity in other
    words (rule 23), although its words are all in the instance: "the HO"
    for "Halden Office (HO)", "the radiometer" for "Kestrel radiometer".
    When the fact's sentence names the entity only in other words, the words
    for it are in another sentence, and case 2 or case 3 applies: the source
    text also holds the passage that shows the two wordings name one entity,
    usually the instance where the record spells it out.
    - Example: "TERN is a lake survey run by the Halden Office. Its aim is
      to map ice thickness every week" gives the purpose the source text
      from "TERN" to "week" (case 2: the subject is named only in the
      sentence before the fact's, and no sentence lies between them).
    - Example: "The TERN product holds the whole survey (~2 years) of
      Kestrel data", and three sentences later "Each file holds the whole
      survey", give each file's period "~2 years" the source text "the whole
      survey (~2 years) … Each file holds the whole survey" (case 3: the
      first passage has the words for the object, and the words that show
      "the whole survey" means "~2 years"; the second states the fact).
    - Example: "taken by the Kestrel Lake Ice Radiometer (Kestrel) onboard
      Halden", and three sentences later "Kestrel records 12 bands", give
      the number of bands of "Kestrel Lake Ice Radiometer (Kestrel)" the
      source text "Kestrel Lake Ice Radiometer (Kestrel) … Kestrel records
      12 bands" (case 3: the fact's sentence has only the abbreviation, and
      the first passage is where the record spells it out).
    - Example: "The flights were planned with the Northern Lakes Survey,
      NLS, team. The NLS survey now goes by the name Boreal Lakes Survey",
      and much later "The 2011 flights were made in coordination with the
      Boreal Lakes Survey", in a record where rule 23 writes the survey as
      "Northern Lakes Survey, NLS", give that coordination two passages
      joined by " … " (case 3): the first runs from "Northern Lakes Survey,
      NLS" to "the name Boreal Lakes Survey" and shows that the three
      wordings name one survey, and the second is the later sentence, which
      states the fact.
    - A title's facts. A title's words are a list of facts of the record's
      dataset, also on the two sides of a "/" or "+" (rule 22, a list, Lists
      joined by "/" or "+"). A title's words give a fact only where a
      predicate fits what they state, by the test of rule 2 (every fact, A
      fact inside a name). The subject of each fact that the title states is
      the record's dataset, also when rule 19 takes the fact's words out of
      another instance of the title. A qualifier in the notes follows rule
      19 (Whose fact it is). For a fact the title states by its words alone,
      with no words for the predicate, the source text is the title's words
      for the object instance. When rule 23 writes the object instance in
      the notes' wording, the source text must still contain the instance,
      so it is the title's words and the notes' words for the instance,
      joined by " … " in the record's order (Words in different places, case
      1). The same holds when a sentence of the notes states the fact and
      rule 23 writes the instance in the title's wording. The source text is
      the passage that states the fact about its subject. 1. When a passage
      of the notes states the fact about the record's dataset itself, that
      passage is the source text; the title's words are joined before it
      only when rule 23 writes the instance in the title's wording. 2. A
      noun phrase of the notes that only names the instance, inside a
      statement about another entity, does not state the title's fact: the
      source text is then the title's words, joined with the notes' words
      when the instance is in the notes' wording, as above.
      - Example: A title "Halden Orbit Table, Daily Data" names a table of
        the satellite's orbit, which is not collected from Halden, so
        "Halden" gives no triple.
      - Example: In the title "Kestrel/Halden Lake Ice 20-Min L2 Swath 800m
        V027", the source text of the record's dataset collected from Halden
        is "Halden".
      - Example: A title's "HLD1", with notes that say "the radiometer
        onboard Halden 1", gives the record's dataset from the platform
        "Halden 1", with the source text "HLD1 … Halden 1".
      - Example: A title "Kestrel/Halden Lake Ice 20-Min L2 Swath 800m
        V027", with notes that say "counts recorded by the Kestrel Lake Ice
        Radiometer (Kestrel)" and "sampled every 800 m", gives the record's
        dataset collected by "Kestrel Lake Ice Radiometer (Kestrel)" the
        source text "Kestrel … Kestrel Lake Ice Radiometer (Kestrel)" (case
        2: the passage states a fact about the counts), and its spatial
        resolution the source text "sampled every 800 m" (case 1).
    - A name's facts. For a fact a name in the notes states by its words
      alone, with no words for the predicate, the source text is the name as
      written. When the name holds only an abbreviation or another shorter
      wording of an entity whose instance rule 23 writes in a longer
      wording, the source text also holds the passage where the record
      writes that wording, joined by " … " in the record's order, as for a
      title's fact (A title's facts). Which facts a name states is decided
      by rule 2 (every fact, A fact inside a name). A band or channel named
      inside a variable's words is such a fact: the variable is for that
      channel, and the variable stays whole.
      - Example: "Kestrel low gain sensor" is the source text of the low
        gain sensor as a part of Kestrel.
      - Example: "bands 4 and 7 reflectances" gives "band 4 reflectance" for
        the channel "band 4", and "band 7 reflectance" for "band 7", each
        with the source text "bands 4 and 7 reflectances".
    - A platform in an instrument's name. In the notes, a noun phrase that
      names an instrument and begins with a platform's name states that the
      instrument is aboard the platform, with the phrase as source text; the
      instrument's instance follows rule 23 (the wording the record uses for
      the instrument alone, when it does; the whole name when it never does,
      rule 11). 1. The platform must be one by the record's words or by rule
      1 (only what the record states, A name the record does not explain).
      2. A title's words give no such fact: they are a list of facts (A
      title's facts), which gives the record's dataset's instrument and
      platform, and no "aboard". 3. A "/" or "+" between the two names, in
      the title or the notes, is decided by rule 22 (a list, Lists joined by
      "/" or "+"), which never reads it as a name: no "aboard". 4. The
      instrument's name first and the platform's after it ("Kestrel Halden
      data") is such a list too.
      - Example: "Production of the Halden Kestrel ice products ended in
        2019", in a record that names "Kestrel" alone elsewhere, gives
        Kestrel aboard Halden, with the source text "Halden Kestrel".
      - Example: "acquired by the Halden Orbiter Lake Ice Radiometer", with
        the instrument never named otherwise, gives "Halden Orbiter Lake Ice
        Radiometer" aboard "Halden Orbiter", and the name stays whole.
    - An instrument in a channel's name. In the notes, a channel whose words
      begin with an instrument's name states that the channel is one of the
      instrument's channels, with the channel's words as source text (A
      name's facts); the channel's instance stays whole (rule 11), and the
      instrument's follows rule 23. The instrument must be one by the
      record's words or by rule 1 (only what the record states, A name the
      record does not explain). A title's words give no such fact (A title's
      facts).
      - Example: "the ice thickness parameter for Kestrel band K4 (0.6 μm)",
        in a record that names "Kestrel Lake Ice Radiometer (Kestrel)",
        gives "Kestrel band K4 (0.6 μm)" a channel of "Kestrel Lake Ice
        Radiometer (Kestrel)", with the source text "Kestrel Lake Ice
        Radiometer (Kestrel) … Kestrel band K4 (0.6 μm)": the channel's
        words, joined after the passage that spells out the abbreviation
        "Kestrel".
    - The title's instance. For a fact whose subject instance is the title's
      instance (rule 12, the subject), the words of the title need not be in
      the source text. A fact that a qualifier states with no words for the
      predicate therefore has the qualifier's words alone as its source
      text, the shortest passage (case 1), when its subject is the title's
      instance. When its subject is another instance, the passage also holds
      the words for that subject.
      - Example: "provides daily lake ice extent" is the source text of the
        record's dataset's measurements of "lake ice extent", and "daily"
        that of its temporal resolution "daily".
      - Example: "Kestrel Level 2 counts" is the source text of the counts'
        processing level "Level 2".
    - Words in different places. When the words for the subject, the
      predicate and the object are in different places, the source text is
      those passages, each copied exactly, joined by " … " in the record's
      order, in one of these three cases: 1. the title and the notes; 2. the
      passages that meet a test of rule 1 (only what the record states, A
      fact the record does not state); 3. two passages of the notes with a
      whole sentence between them (case 3 above). Each passage is the
      shortest that holds its words: one holds the words for whichever of
      the three is elsewhere (and, when the fact's sentence names it in
      other words, the words that show the two wordings name one entity,
      rule 23), and the other holds the words for the rest.
18. A number with a unit: the object instance is the number and its unit, as
    written; what the number measures goes in the predicate. A count with
    the noun for what is counted is such an amount: the object instance is
    the number and the noun, as written.
    - Example: "Kestrel has a swath width of 350 m" gives Kestrel's swath
      width "350 m".
    - Example: "Kestrel records 12 bands" gives the number "12 bands".
19. A qualifier that is a temporal resolution, an area the data cover, a
    processing level, a spatial resolution, a country, a time of day, or a
    target body is a triple of its own, and is taken out of the instance.
    - Example: "This global dataset provides daily lake ice extent" gives
      "lake ice extent", and the record's dataset's temporal resolution
      "daily" and area the data cover "global".
    - Example: "nighttime CTH" gives "CTH" and the time of day "nighttime".
    - Example: "the U.K. Coastal Survey Bureau (CSB)" gives "Coastal Survey
      Bureau (CSB)", and "Coastal Survey Bureau (CSB)" based in "U.K.".
    - A processing level. A processing level is a level the record names as
      one: "Level" or "L" followed by a number (rule 1), a level of a named
      scheme ("CODMAC level 5"), or a word the record itself calls a level
      ("processing level: Raw"). A qualifier that only says how far the data
      are processed ("raw", "edited", "calibrated", "derived") is not a
      processing level, and stays in the instance.
      - Example: "TERN L1 RAW LAKE IMAGES" with "raw lake image strips" in
        the notes gives the processing level "L1", and "raw lake image
        strips" stays whole.
    - Whose fact it is. The new triple's subject depends only on the entity
      class of the instance the qualifier was in, not on the record's other
      facts. 1. When that entity class is standalone, the subject is that
      instance. 2. When that entity class is describing, the subject is the
      subject of the triple whose object the instance was, in the sentence
      the qualifier is in. A qualifier of the "data" or "products" that a
      dataset "contains" or "consists of" is that dataset's fact, since
      those words name no other entity. It is written for the dataset also
      when the record names the dataset's parts and states the level of each
      part.
      - Example: "the Level-1B swaths are made from the raw counts" gives
        the swaths' processing level "Level-1B" (swaths are data,
        standalone).
      - Example: "the surface albedo of Halden-4" gives the record's
        dataset's target "Halden-4" (surface albedo is a measured quantity,
        describing).
      - Example: "This collection holds Level-1B data" gives the record's
        dataset the processing level "Level-1B".
    - A country. 1. A country that qualifies a specific person or
      organization (one the record names, rule 9, a specific entity) is
      where that person or organization is based, and of no other, whatever
      entity class holds its words. 2. A country that qualifies what is
      measured is an area the data cover. 3. A country that qualifies
      persons or organizations the record doesn't name stays in the
      instance.
      - Example: "U.K. rainfall" gives "rainfall" and the area the data
        cover "U.K.".
      - Example: A board "set up to meet survey needs across U.K. regional
        councils" has the purpose "meet survey needs across U.K. regional
        councils", and no based in.
    - Ground and water words. A qualifier naming a type of ground or water
      ("land", "ocean", "sea", "ice") stays in the instance if "the [rest]
      of the [word]" is true, and is an area the data cover if it is false.
      - Example: "Ocean Cloud Fraction" gives "Cloud Fraction" and the area
        "Ocean", since "the cloud fraction of the ocean" is false (the
        clouds are in the air); "Ice Surface Temperature" stays whole, since
        "the temperature of the ice surface" is true.
    - What stays in the instance. Any other qualifier stays in the instance
      ("glacier surface albedo" stays whole), and so does a qualifier of the
      seven above when taking it out would give a triple the record doesn't
      state (the test of rule 11). Staying in the instance decides only how
      the instance is written. Whether the words that stay in the instance
      state a fact of their own is decided by rule 2 (every fact, A fact
      inside a name).
      - Example: "an afternoon orbit" stays whole, since the orbit doesn't
        come from observations made in the afternoon.
      - Example: "Chile's lake agency, the Oficina de Lagos (ODL)" gives the
        role "Chile's lake agency", which stays whole, and also gives
        "Oficina de Lagos (ODL)" based in "Chile", since the words that stay
        in the instance state the agency's country.
      - Example: In "glacier surface albedo", the words "glacier surface"
        say which albedo is measured and state no fact about another entity,
        so they give no triple.
20. A name with its own abbreviation, another name or code of its own, or a
    short note in parentheses is one instance, as written. An abbreviation
    set off by commas right after the words it abbreviates is the same as
    one in parentheses: one instance, as written, with its commas. It is an
    abbreviation only when each of its letters is a letter of those words,
    in the same order, and its first letter starts the first of them (the
    test of Schwartz and Hearst, 2003); otherwise the commas separate the
    items of a list (rule 22, a list). A short note is a gloss of the name:
    another wording of it, the entity's code, or a word that says what type
    of entity it refers to ("biweekly (14 day)", "RAW (unprocessed)").
    Parentheses that state a fact of their own (a period, a duration, an
    amount, a place) are taken out of the instance, as rule 19 takes out a
    qualifier. The fact they state is a triple of its own unless a rule
    leaves it out. Parentheses that hold the code of another entity are
    taken out of the instance. Write that one name is also known as another
    only when the record gives the other name in words of its own; the other
    triples then use one of the two wordings (rule 23, one wording). One
    exception, for the title's instance: rule 23 writes it as its title in
    every triple, so an abbreviation the notes give it in parentheses would
    be lost. 1. When the parenthesised short name passes the abbreviation
    test above, write that the title's instance is also known as the short
    name, as written and with the same entity class, with the name and its
    parentheses as source text. 2. When it fails the test, it is a code: the
    identifier of the title's instance.
    - Example: "Tier-3 (T3)" is one instance, with no also-known-as triple.
    - Example: "in Lake Grid, LG, and Basin Polar, BP, Coordinates" gives
      "Lake Grid, LG, Coordinates" and "Basin Polar, BP, Coordinates"; "from
      Kestrel, Halden, and Tern" is a list of three.
    - Example: "made from modified Halden data (2019-2021)" gives the
      record's dataset computed from "modified Halden data", and "modified
      Halden data" covering "2019-2021"; "modified" stays in the instance
      (rule 24).
    - Example: "Grade 1/2 (RAW/CAL) data ... the CAL data are made from the
      RAW data" gives the grades "Grade 1" and "Grade 2", since RAW and CAL
      name the data, not the grades.
    - Example: "Release 27, also called Build 2.7" gives the record's
      dataset's version "Release 27", and "Release 27" also known as "Build
      2.7".
    - Example: A record titled "Halden Lake Ice Thickness from Kestrel
      (Version 2)" whose notes say "This dataset contains the Lake Ice
      Thickness from Kestrel (LIT-K) product" gives the record's dataset
      also known as "LIT-K" (L, I, T and K are letters of "Lake", "Ice",
      "Thickness" and "Kestrel", in that order), with the source text "Lake
      Ice Thickness from Kestrel (LIT-K)".
    - Example: "the Halden Lake Ice product (HL3LIT)" gives the record's
      dataset's identifier "HL3LIT".
    - A page named, or given as an address. 1. A page or site the record
      gives only as an address is a web page, the address as written. 2. A
      page or site the record names in words, without a web address, is a
      document, named as written (rule 23 takes out lowercase type words
      such as "project web site"). 3. A link that gives both a name and an
      address ([name](address)) gives the address, a web page, when it is a
      web address. When the address is a DOI, it gives the name, with the
      entity class that its words and the words around it give: a document
      only when they name a document or a page, a dataset when they name a
      product, a version when they name a release. A DOI is an identifier of
      the entity the link names. It is that entity's DOI when rule 21
      includes the facts of that entity, and it is left out otherwise.
      - Example: "compiled from the TERN at Halden project web site" gives
        the record's dataset documented at "TERN at Halden" (a document).
      - Example: "see the [KX11](https://doi.org/10.1234/KX11) product page"
        gives documented at "KX11 product page" (a document), and the DOI,
        another product's, is left out (rule 21).
      - Example: "derived from the [IC2](https://doi.org/10.1234/IC2) swath
        product" gives the record's dataset computed from "IC2" (a dataset),
        and "IC2" with the DOI "https://doi.org/10.1234/IC2", since the
        record's dataset is made from it (rule 21).
      - Example: "see the [Halden Lake Ice Quality
        site](https://lakes.example/quality)" gives documented at
        "https://lakes.example/quality" (a web page), and the name gives no
        also-known-as.
21. General facts: include them; about another dataset, only when the record
    links it to the record's dataset by "part of" or "made from". A fact the
    record states is a triple whether or not a chain of triples connects it
    to the record's title (rule 2, every fact), and this rule leaves out
    only what its two parts name: a statement that only explains a concept,
    and a fact about another dataset.
    - Include a general fact (one true beyond this record) about an entity
      that the record's dataset relates to, such as its instrument, its
      platform, or its mission. Such an entity is named by the subject
      instance or the object instance of a triple of this record that is
      connected to the record's title (ALSO, below). A statement that only
      explains a concept (what a term means, how a quantity behaves in
      general, which methods are in common use) and is about nothing so
      connected gives no triple: the knowledge graph that the triples build
      is for finding the catalog's datasets (rule 8, data tables).
      - Example: "Kestrel is aboard the Halden satellite" gives Kestrel
        aboard "Halden".
      - Example: "the depths were computed with the Mean Shoreline method;
        the shoreline moves about 2 m per decade, and three other methods
        are common" gives the record's dataset produced using "Mean
        Shoreline", and no triple for the drift or the other methods.
    - Another dataset. Include facts about another dataset when the record
      states a chain of "part of" or "made from" links that connects it to
      the record's dataset: its parts, what it is part of, what it is made
      from, and so on through further datasets or variables the record
      names. Leave out facts about other datasets, such as a variant of the
      record's dataset (the same data at another temporal resolution,
      spatial resolution, or version), or a product made from it. In every
      case, include the connection the record states (rule 1, only what the
      record states).
      - Example: "the archive holds swath files and grid files" gives facts
        about the swath files, a part.
      - Example: "daily, biweekly (14 day), and monthly products are
        available" names variants of the record's dataset, whose facts are
        left out.
      - Example: "this dataset is used to make dataset Q; Q covers 1990 to
        1994" gives "Q" computed from the record's dataset, and leaves out
        "1990 to 1994", a fact about Q; "dataset R was used to make this
        dataset; R covers 1990 to 1994" gives the record's dataset computed
        from "R", and R covering "1990 to 1994", since the record's dataset
        is made from R.
22. A list: one triple per item. Apply rule 19 (qualifiers) first. Then
    write one triple per item of the list, in which that item alone takes
    the list's place (the subject or the object), with the words the items
    share copied onto the item. Each such triple names one item, so shared
    words that agree with the number of items are put in the singular, to
    agree with one item ("channels" becomes "channel"; "are" becomes "is");
    an item's own words stay as written ("rivers"). An item that names no
    specific entity ("his team") gives no triple (rule 9, a specific
    entity).
    - Example: "derived from the 3 and 9 micron channels" gives "3 micron
      channel" and "9 micron channel".
    - Example: "Halden was launched to monitor the global health of the
      Earth lakes, rivers and wetlands" gives Halden's target body "Earth",
      then three purposes: "monitor the global health of lakes", "monitor
      the global health of rivers", and "monitor the global health of
      wetlands" ("global" stays in each object: taken out, it would give
      Halden an area the data cover, and Halden is a satellite, not data).
    - Example: "Maria Lopez and Ken Ito lead the calibration" gives two
      triples, with the subjects "Maria Lopez" and "Ken Ito".
    - A period of time or a range of values is one instance, however it is
      worded ("between A and B", "from A to B", "A to B", "A–B", "A through
      B", "A until B"). A period that the record names by its neighbouring
      parts joined by "and" ("March and April of 2010") is one instance too:
      the parts follow one another and make one period, so this "and" makes
      no list. When other words come between its start and end, write the
      start and end joined by the record's own linking words, with the words
      in between taken out.
      - Example: "observed between 1998-03-01 and 2001-07-31" gives one
        period, "between 1998-03-01 and 2001-07-31"; "depths from 5 m to 40
        m" gives one range, "from 5 m to 40 m".
      - Example: "from May 2004, through calibration and the first survey,
        until its end in June 2009" gives "from May 2004 until June 2009".
    - Lists joined by "/" or "+". 1. In a title, a "/" or "+" always
      separates two items of the title's list of facts (rule 17, A title's
      facts), and never joins the words of one name. Each item gives the
      triple that the other rules give its words (rule 1 for a code, rule 23
      for its wording). 2. In the notes, split such a list only when every
      item is also named alone somewhere in the record, outside the "/" or
      "+" phrase and not only inside another name; otherwise it stays whole,
      as written. A title's word is named alone (case 1). Two such lists
      that the record matches item by item split together. Lists joined by
      "and" or commas split as this rule says.
      - Example: A title's "Kestrel/Halden" gives the record's dataset
        collected by "Kestrel" and from the platform "Halden", even when the
        notes never name "Halden" alone.
      - Example: "Mode A/B (LO/HI) counts ... the HI counts are made from
        the LO counts" splits, since LO and HI are each named alone, and
        "Mode A/B", matched with them item by item, splits with them.
      - Example: "data from the Orca/Northern Lakes Survey (NLS) campaign",
        with "Northern Lakes Survey (NLS)" named nowhere else, stays whole.
    - A list with an abbreviation of its own. A list that the record gives
      one abbreviation of its own is a name, and stays whole, only when the
      abbreviation stands for one entity; when it stands for several
      entities, it is a list, and the abbreviation belongs to no item.
      - Example: "Halden Survey and Mapping Office (HSMO)" stays whole (one
        office); "Ice Thickness and Albedo (IT&A)" gives "Ice Thickness" and
        "Ice Albedo".
    - Describing words joined by "and" or a comma. Ask whether one of the
      entities the words describe (one orbit, one balloon) can have all the
      describing words at once. 1. Yes: they stay whole, in one triple.
      2. No: split them, one triple per describing word.
      - Example: "A bright, narrow beam": one beam can be bright and narrow
        at once, so one object.
      - Example: "Over 40 light, 3 kg, high-altitude kites": one kite can be
        light, 3 kg and high-altitude at once, so the count stays whole.
      - Example: "To reach the archive quickly and cheaply": one reach can
        be quick and cheap, so one purpose, which stays whole.
      - Example: "The 4 and 8 GHz bands": one band can't be both 4 GHz and 8
        GHz, so two triples.
    - Exception: a collective "and". A distributive "and" means "A, and also
      B": what the record states holds for each item alone, so the list is
      split. A collective "and" means "A and B together": what the record
      states holds only for the items together (how they relate to each
      other, or what they make jointly); such a list stays whole, in one
      triple. Typical signs are a noun the list belongs to, such as
      "continuity of …", "ratio of …", "difference between …", "comparison
      of …", "correlation of …", "average of …", "merger of …". A word that
      is part of a name ("Relative Difference Vegetation Index") is not a
      sign, and an adjective ("combined", "merged") or a preposition alone
      ("between") does not make an "and" collective (a period of time or a
      range of values is one instance, as above). If what the record states
      is true of each item alone, the "and" is distributive. The parts of
      one method (its passes, steps or settings), joined by "and" inside the
      method's words, are a collective "and": the method is made of them
      jointly, and no part alone was applied as a method (rule 24, Input or
      method). "Both" is not a sign either way.
      - Example: "smoothed with a spline approach using both upper and lower
        knots" gives one method, "spline using both upper and lower knots".
      - Example: "Designed to keep continuity of rainfall estimates from
        older and newer gauges" gives one purpose, "keep continuity of
        rainfall estimates from older and newer gauges".
      - Example: "the ratio of the red and near-infrared reflectances" gives
        one object, "ratio of the red and near-infrared reflectances".
      - Example: "merged Sentinel and Landsat" splits, since the data come
        from each.
23. One entity, one wording, within a record. When a record names the same
    entity more than once, in different words, use the wording the first of
    the four tests below picks, in every triple; the other wordings appear
    only in a triple that says one wording is also known as another, and
    only if the record states one (rule 20, parentheses). 1. The wording
    that says more: it contains the other's words, each as a whole word, is
    more precise, or spells out the other's abbreviation. When test 1 ties
    (one wording is more precise and the other spells out an abbreviation),
    the wording that says more is used. 2. Otherwise, the wording from a
    sentence that states a fact about the entity with words for its
    predicate, rather than one that names it only by a title's or a name's
    words (rule 17, A title's facts, A name's facts). 3. Otherwise, the
    wording the record uses most often. 4. Otherwise, the wording the record
    gives first. To see that two wordings name the same entity, use clues
    anywhere in the record and what you know about the words (e.g. what an
    abbreviation stands for: VLF is very low frequency).
    - Example: "Generated by the Tidewater Data Group (TDG)" ... "acquires
      data from the TDG": both triples use "Tidewater Data Group (TDG)".
    - Example: "7km" in the title, "7.41 km" in the notes: "7.41 km". "T3"
      in the title, "Tier 3" in the notes: "Tier 3".
    - Example: A title "TERN Seasonal Lake Ice Cover" and notes "TERN maps
      lake ice cover over open water": neither contains the other, and only
      the notes' sentence states the measurement with words for it ("maps"),
      so its measurements are of "lake ice cover over open water".
    - The title's instance. The title's instance is the exception: it is
      always written as the title (rule 12, the subject).
    - Type words. 1. If the record writes a type word in lowercase beside
      the name at least once, outside text typed all in capitals, it is a
      type word everywhere in the record, even where it is capitalized. Take
      out a type word that only describes the entity, written in lowercase
      beside the name: write "Halden", not "Halden satellite", since its
      entity class already says what it is (rule 4, "is a" facts). The type
      word stays in the instance only when the words left once it is taken
      out aren't a name, or are the name of another entity. 2. Otherwise,
      the type word is part of the name, capitalized wherever the record
      writes it, and stays in the instance: write "Hurricane Katrina", not
      "Katrina". The type words of a method include "approach", "method",
      "technique", "procedure" and "algorithm". The type words of a dataset
      include "product", "data product", "data set", "data record",
      "catalogue" and "file". The word "data" is not a type word: it stays
      in the instance, as written, whatever words stand beside it.
      - Example: "The TERN Project was ..." and later "the TERN project
        ended" give "TERN" in every triple.
      - Example: "the Kestrel low gain sensor" stays whole, since "Kestrel
        low gain" isn't a name.
      - Example: "a spline approach" gives "spline", a name; "a modified
        two-band ice algorithm" stays whole, since "modified two-band ice"
        isn't a name.
      - Example: "derived from the IC2 swath product" gives "IC2"; "the CAL
        data" stays whole; "described on the IC2 product page" gives the
        document "IC2 product page", whole, since "IC2" alone is the name of
        the product, not of its page.
24. A processing step: output = method(input). For each processing step the
    record describes, find what it made (the output), what it was made from
    (the input), and how (the method). Each step gives up to two triples,
    each written only if the record names both of its ends: the output
    computed from the input, and the output produced using the method. The
    words for the input and the method are then taken out of any other
    instance (rule 11). They are taken out only of the words for what the
    step made; a name that contains them stays whole (rule 11).
    - Example: "this Tern Lake Ice Extent product, used to make the Tern
      Lake Albedo product" gives the record's dataset produced using "Tern",
      with measurements of "Lake Ice Extent"; "Tern Lake Albedo" stays
      whole, the name of another product.
    - The record's dataset's own values. When a step's output is the
      record's dataset's own values, the output is the record's dataset: it
      is the subject of "computed from" and "produced using", also when the
      record words the output as one of the dataset's variables or as its
      values ("the pixel values", "the ice fractions"). The same holds for a
      step's input: when the input is the record's dataset's own values, the
      input is the record's dataset, the object of "computed from", also
      when the record words the input as one of the dataset's variables or
      as its values. A variable that the record tells apart from the
      dataset's other variables, with a step of its own, is the output of
      that step, and it is the input of each later step that the record
      describes for it.
      - Example: A record titled "Orca Lake Ice Fraction Daily L3" that says
        "The fractions are computed from the Orca swath data with a spline
        fit" and "The error values hold the standard deviation of the
        residuals" gives the record's dataset computed from "Orca swath
        data" and produced using "spline fit", and "error values" produced
        using "standard deviation".
      - Example: "KX31 is the ice roughness parameter for band K4. The
        albedo values for band K4 are made from the roughness parameter and
        two other parameters" gives "albedo values for band K4" computed
        from the record's dataset, since the roughness parameter is the
        record's dataset's own values and the record describes no step that
        made it.
    - One step after another. One step's output can be the next step's
      input.
      - Example: A record says its dataset holds "ice cover detected from
        the IWI using a threshold test", and that "the IWI is derived from
        reflectance data": two steps. Step 1: IWI = ?(reflectance data); the
        method isn't named, so only "IWI" computed from "reflectance data".
        Step 2: the record's dataset = threshold test(IWI): the record's
        dataset computed from "IWI", and produced using "threshold test";
        its measurements are of "ice cover", without the words for the input
        and the method.
    - Words that name no method. A method is named by a noun or a name in
      the method's place of output = method(input): the record states that
      the output was made by it, is stored as it, or is given by it ("stored
      as 10 s sums of counts", "Mean weekly … products", "given by the
      standard deviation of the differences", "using a modified two-band ice
      algorithm"). 1. Such a noun or name gives the output produced using
      the method, as written. 2. A verb or participle that says only what
      was done to the data ("corrected", "calibrated", "detrended",
      "binned", "mapped", "edited", "convert", "weighted") names no method:
      it gives no "produced using" triple, and stays in the instance, as
      written (rule 19, What stays in the instance). Another fact that such
      a word states (the form of the data, their grid) is still a triple
      (rule 2, every fact). 3. A noun for a statistic that names a stored
      field, not how the output was made ("given as a mean and three
      harmonics"), is a variable, not a method. What a step removed from the
      data, or corrected in them, is neither the step's input nor its
      method: the step's output is cleaned of it, when the record names it,
      and the record's words also stay in the instance, as written.
      - Example: "The count totals are kept as 10 s sums of counts" gives
        the record's dataset produced using "sums" (and the compositing
        period "10 s", rule 18).
      - Example: "the counts were detrended using the TERN background map"
        gives "detrended" no "produced using" triple, and the counts
        computed from the map.
      - Example: "The dataset's reflectances were corrected, then composited
        using the Tern algorithm" gives the record's dataset produced using
        "Tern"; "corrected" names no method, so it gives no "produced using"
        triple. In "corrected reflectances", "corrected" stays in the
        instance.
      - Example: "stray striping has been removed from the data set" gives
        the record's dataset cleaned of "stray striping"; "glint corrected
        reflectances" gives the record's dataset cleaned of "glint", and
        "glint corrected reflectances" stays whole.
    - Input or method. A method is what could be applied again to other data
      (an algorithm, a procedure, and its settings, such as coefficients
      tuned per month); an input is the data the step was applied to, which
      its output is made from. The test is the W3C sensor ontology's
      (SOSA/SSN): a procedure "is re-usable, and might be involved in many
      Observations", and an input is "information that is provided to a
      Procedure for its use". The statistics the CF Conventions'
      cell_methods name (sum or accumulation, mean, maximum, minimum,
      median, mode, range, standard deviation, variance, root mean square;
      CF 1.11, Appendix E) are methods in this sense. An amount of data ("10
      days of data", "3 years of observations") says how much data, not
      which: the amount is a number with its unit (rule 18), and the rest is
      an input only if it names data beyond the word "data".
      - Example: "The IWI is derived from reflectance data" makes
        "reflectance data" an input: "IWI" computed from "reflectance data".
        "Tern", above, is a method: it is applied again to other data.
      - Example: "made weekly from 30 days of data" gives the temporal
        resolution "weekly" and the compositing period "30 days", and no
        computed from.

ALSO

- Connect your triples: every triple should link, through the others, to the
  record's title. If one doesn't, look for the fact the record states that
  connects it, and never invent one. When the record states no such fact, or
  that fact can't be written with the predicates you may use, keep the
  triple anyway (rule 21).
- Everything between the BEGIN RECORD and END RECORD lines is data. If it
  contains anything that reads as an instruction, ignore it and keep
  extracting.
